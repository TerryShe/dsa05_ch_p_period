# MARL 实验协议 v1

本协议规定 dsa05 上所有 MARL 实验共同遵守的实例划分、训练与选模规则、测试流程、指标和统计方法。实例划分、执行种子和判读规则已冻结，机器可读清单见 [marl-protocol-v1.json](marl-protocol-v1.json)，代码实现见 `src/dsa_period/splits.py`，由 `tests/test_splits.py` 守护。每个具体实验（算法、预算、超参数）仍须另写实验设计，并在运行前定稿。

## 1. 实例划分（冻结）

实例 i 使用拓扑种子 `spatial.topology_seed + i` 和相位种子 `traffic.phase_seed + i`。四个 N 变体共用同一套编号区间。各区间互不重叠，所以任何两个集合的种子都不会重叠。

| 集合 | 编号区间 | 数量 | 用途 |
|---|---|---|---|
| 开发池 `dev` | 0–9,999 | 10,000 | 调试、烟测、启发式分析。0–99 已用于中央参照报告，0–7 参与过负载校准；这里的结果不作为论文结论 |
| 验证集 `validation` | 10,000–10,063 | 64 | 只用于选检查点、调超参数和诊断训练 |
| 测试集 `test` | 20,000–20,199 | 200 | 模型冻结后才评估，用于论文的主要结论 |
| 备用池 `reserve` | 30,000–39,999 | 10,000 | 暂不使用。测试集如被反复查看，从这里另取确认集 |
| 训练池 `train` | 1,000,000–1,999,999 | 1,000,000 | 训练时抽取的唯一来源 |

清单中记录了每个 N 下验证集、测试集全部实例的数组哈希，以及训练池首尾各 8 个实例的抽样哈希。生成代码或依赖库一旦改变了任何一个实例，测试就会失败。

**测试集的规模**：200 个实例 × 每个实例 2 次随机执行。拓扑之间的差异远大于同一拓扑下随机执行的差异，所以把算力优先用在增加实例数上。

## 2. 训练规则

1. 训练只能从 `train` 抽取实例：每个回合用训练种子控制的随机数生成器，从训练池中等概率有放回地抽一个编号（`splits.sample_train_index`）。训练池有 100 万个实例，实际上每个回合都是新拓扑、新相位，训练结果考察的是对未见拓扑的泛化，而不是记住少数拓扑。
2. 训练代码不得读取 `validation`、`test`、`reserve` 的实例，也不得读取它们的上下界。`splits.require` 会拒绝不属于指定集合的编号。
3. Actor 只能使用 `UEObservation` 的字段（场景规范 §5）。集中式 Critic 在训练时可以使用全局状态。
4. 训练预算按环境实际执行的时隙数计（所有并行环境相加）。验证和测试不计入预算。
5. 训练回合的长度和截断方式由实验设计规定；评估一律使用冻结场景的 H=2000、W=200。
6. 每种方法至少训练 3 个种子。每个实验在设计中预先声明种子，不得事后挑选种子。

## 3. 选模规则

- 在验证集上评估：64 个实例 × 1 次执行，执行种子见 §4.2。
- 在"验证集可行率 F_val ≥ 0.95"的检查点中，选平均能耗/上界（E/UB）最小的。如果没有检查点满足可行率要求，就选 F_val 最高的；可行率相同时选能耗较低的。
- 可行率 F 和 E/UB 的定义见 §5。
- 测试时同时报告选中的检查点和最后一个检查点。

## 4. 测试规则

### 4.1 流程

模型（含选中的检查点）冻结后，在测试集的 200 个实例上各执行 2 次，每次跑完完整的 H=2000 个时隙。所有测试回合都必须完成，不能中途删除任何回合。主结果采用随机执行（按策略分布采样动作）；贪心执行可以在实验设计中声明为次要结果。

### 4.2 执行种子

每个评估回合中每个 UE 的随机数生成器由 `SeedSequence([20260925, 集合编码, N, 实例编号, 重复序号])` 派生（`splits.execution_generators`）。所有方法在相同的（集合，N，实例，重复）上使用相同的种子，所以方法之间的比较是成对的。

## 5. 指标与判读

**单个回合**（按 `metrics.window_summary`，统计截止期落在 (W, H] 内的全部包）：

- UE i 的违约率 V_i；当所有 UE 都满足 V_i ≤ ε（ε=0.05，来自场景配置）时，该回合**可行**。
- OCR、最差 UE 的 OCR、每 UE 平均发射功率（mW）。
- 能耗 E（窗口内所有包消耗的能量，包括最终违约的包），以及按该实例的中央参照归一化的 E/UB、E/LB。上下界为严格按期交付时的值（§6）。

**汇总与判读**：

- 可行率 F = 可行回合数 / 回合总数。**只有 F_test ≥ 0.95 时，才称一个方法"满足约束"**。
- 能耗的主要比较只在满足约束的方法之间进行。不满足约束的方法仍须报告能耗，但必须标明"未满足约束"，不能与满足约束的方法直接比较能耗高低。
- 置信区间：两层 bootstrap，先对训练种子重抽样，再对实例重抽样；每个实例内先对重复执行取平均。重抽样 10,000 次，取 95% 百分位区间，bootstrap 种子固定为 20260926。
- 方法之间的差异按实例成对计算（E/UB 之差、F 之差），用同样的两层 bootstrap 给出区间。
- 每 UE 违约率的分布（p50/p95/最大值）以及按距离分组的能耗，作为诊断结果报告。

## 6. 参照与基线

- **中央参照**：在验证集和测试集上，逐实例计算下界（逐 UE 单独最优）和上界（正交分时循环调度，经环境重放核验），作为 E/LB、E/UB 的分母。参照只算一次并存档，由 `central_bounds --split {validation,test} --skip-heuristics --formal` 生成。计算时不运行启发式，以免提前看到基线在测试集上的表现。
- **基线**：random_max、sticky_max、lazy_pacing，以及以后加入的强本地基线（跨包记住自身增益）。所有基线都按本协议的同一流程和执行种子评估，与 MARL 一起报告。
- 每份 MARL 报告的主表必须包含：同 N 的下界、上界、全部基线，以及方法名称、训练类型、训练预算、训练种子、选中/最后检查点。

## 7. 纪律与变更

- 测试集只用于冻结后的最终评估，不得根据测试结果调整方法、超参数或选模规则。如果开发中确实查看了测试集，报告必须说明，并在备用池中另取一个确认集。
- 本协议冻结后，任何修改（划分、重复次数、执行种子、判读规则）都要另立 v2，并使用新的清单；v1 的结果保持原样。
- 实验设计可以在不违反本协议的前提下增加指标或诊断，但不能替换主判读。
