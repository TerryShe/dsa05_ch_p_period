# EXP-DSA05-011B 的评估切片与压力集登记

本附录登记 EXP-DSA05-011B（防饿死选模与延长训练下的紧迫摘要复验）使用的两个开发集合，依据[设计](../experiment-designs/011b-guarded-selection-extended-training_20261012.md) §2.3、§3.4 与 §4。

- 协议 v2 的冻结核心不变。EXP-008、EXP-009、EXP-010、EXP-011 的登记不变：重新生成后，四份清单逐字节相同。
- **机器清单**：[exp011b-sets.json](exp011b-sets.json)，由 `scripts/register_exp008_sets.py` 生成，`tests/test_exp011b.py` 核对。

## exp011b-eval512

| 项目 | 内容 |
|---|---|
| 实例 | 开发池 6,000–6,511（半开区间 [6000, 6512)），512 个部署，不经筛选 |
| N | 6、8、10、12、16 |
| 执行 | 每个部署 1 次，完整 20,200 时隙回合 |
| 种子 | 开发池编码 0，v2 的执行、衰落种子基准与逐 UE 派生，所有方法共用 |
| 用途 | 只用于本实验阶段 4 的评估（设计 §5）。不用于任何检查点选择 |
| 读取方式 | `evaluate_capacity --split dev --screen exp011b-eval512 --grid N --formal`，需干净的已提交工作树；在关口 C 之前不读取 |

## exp011b-stress

| 项目 | 内容 |
|---|---|
| 保留区间 | 开发池 7,000–9,999（半开区间 [7000, 10000)），整段只给压力集用 |
| 读取的部署 | 每个 N 上，前 N 个 UE 中至少有一个距 AP < 5 m 的部署（`starvation.stress_instances`），按实例编号排列 |
| N 与部署数 | N = 8：55 个；N = 12：81 个；N = 16：107 个 |
| 嵌套 | UE 位置在各 N 间嵌套，N = 8 的部署都在 N = 12 中，N = 12 的都在 N = 16 中（测试核对） |
| 用途 | 阶段 1 的饿死诊断与阶段 3 的防饿死选模（设计 §3.1、§3.3）。不用于评估 |
| 读取方式 | `scripts/stress_exp011b.py --formal`，需干净的已提交工作树 |

- 设计中按 exp011-eval512 的比例估计约 75、100、145 个部署。在这一区间中，含近 UE 的部署略少（1.8%、2.7%、3.6%），实际为 55、81、107 个。
  - 三个 N 合计 243 个部署。一个在 3% 的近 UE 部署上饿死的检查点，被检出的概率约 99.9%。
- 清单记录每个 N 的实例列表与摘要（拓扑、阴影、业务与前 8 个时隙的衰落）。

## 保护措施

- `splits_v2.check_dev_range` 拒绝任何与 6,000–6,511 或 7,000–9,999 重叠的普通开发评估。
- `splits_v2.screening_instances("exp011b-stress")` 被拒绝：压力集只能按 N 经几何条件读取，`evaluate_capacity --screen exp011b-stress` 因此不可用。
- 网页可视化工具的允许清单不含这两个集合，直到本实验报告提交；它的专用切片是开发池 5,512–5,999（`web/sim-viewer/README.md`）。

## 登记时的使用核查（2026-10-12）

- v2 开发实例只用过 0–63、1,000–1,399、2,000–2,255、3,000–3,255、4,000–4,511、5,000–5,511。
- 已登记的筛选集与评估集都不含 6,000–9,999。生成压力集清单只读取了 7,000–9,999 的部署几何（UE 位置），没有运行任何策略。
- 第 0 阶段的检查只用训练池、已用过的开发实例 0–63、1,000–1,399，以及已读的 exp011-eval512（反事实的冒烟检查重放了部署 5324）。
