# EXP-DSA05-009 的筛选集与确认集登记

本附录登记 EXP-DSA05-009 使用的两个固定实例集合，依据[设计](../experiment-designs/009-per-n-training-hard-deployments_20261004.md) §3。

- **不改动协议 v2 的冻结核心**：划分区间、集合编码、`EVALUATION_REPEATS`、种子基准及其守护测试都保持原样，EXP-008 的登记也不变（[exp008-registration.md](exp008-registration.md)）。
- **机器清单**：[exp009-sets.json](exp009-sets.json)，由 `scripts/register_exp008_sets.py` 生成，这个脚本同时生成两个实验的清单。`tests/test_exp009.py` 会重新生成清单并逐项核对。
- **摘要的内容**：每个 N 的摘要覆盖拓扑、阴影、业务数组和第 0–7 时隙的衰落。生成摘要时不运行任何策略。

## 1. 筛选集 exp009-screen256

| 项目 | 内容 |
|---|---|
| 实例 | 开发池 3,000–3,255（半开区间 [3000, 3256)），256 个部署 |
| N | 2、4、6、8、10、12、16、20（训练的 N） |
| 执行 | 每个部署 1 次，完整 20,200 时隙回合 |
| 种子 | 开发池编码 0，v2 的执行、衰落种子基准与逐 UE 派生，所有方法共用 |
| 评估方式 | 按 N 训练的检查点只在自己的 N 上评估；混合训练的检查点在全部 N 上评估。一次评估可以只覆盖登记网格的一部分 |
| 选择 | 每个（条件，种子，N）取 F_{0.01}(N) 最高的检查点，再比 F_{0.05}(N)，再取较晚者 |
| 用途 | 只用于按 N 选模与第 1、2 步的规则（设计 §3–§5），不作为论文结论 |
| 读取方式 | `evaluate_capacity --split dev --screen exp009-screen256 [--grid …] --formal`，需干净的已提交工作树 |

代码中的保护：
- `splits_v2.check_dev_range` 拒绝任何与 3,000–3,255 重叠的普通开发评估；
- `--screen` 的 N 必须在登记网格内，且必须 `--formal`；
- `select_exp009` 只接受带该筛选集标记的正式输出，并且对按 N 训练的运行只读取其自身 N 的结果。

筛选实例不进入训练池。S1 的困难层阈值 τ_N 只用训练池实例计算（`configs/exp009-tau.toml`），与筛选集无关。

## 2. 确认集 v2-confirm2

| 项目 | 内容 |
|---|---|
| 实例 | 备用池 30,500–30,999（半开区间 [30500, 31000)），500 个部署 |
| N | 协议网格 {2, 4, …, 32}；N_EDF 另加 36、40 |
| 执行 | 每个部署 1 次 |
| 种子 | 备用池编码 3，v2 的执行、衰落种子基准；逐 UE 派生、不含 N |
| 用途 | EXP-009 的最终比较（设计 §6），冻结后只读一次 |
| 读取方式 | `evaluate_capacity --split v2-confirm2 --confirm-c2 --formal`，需干净的已提交工作树 |

- 学习方法在 N ≤ 20 上用各自 N 的模型，在 N ≥ 24 上用 N = 20 的模型，只作描述。
- 方法清单（`scripts/analyze_exp008_confirm.py --set v2-confirm2` 的 methods 文件，每个种子是一个按 N 的模型层）在读取前冻结。
- v2-confirm1（EXP-008）与本集合不重叠，并且仍未被读取。

## 3. 登记时的使用核查（2026-10-04）

- v2 开发实例只用过 0–63、1,000–1,399、2,000–2,255。
- v2 下没有任何运行读取过备用池实例。
- 第 0 阶段的吞吐测量只使用训练池与已用过的开发实例 1,000–1,063。
