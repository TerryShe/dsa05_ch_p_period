# MARL 实验协议 v2

状态：**冻结（2026-10-01）**，与场景 v2.0 第 6 版一同冻结。机器可读清单为 [marl-protocol-v2.json](marl-protocol-v2.json)，记录种子、划分以及各 N 下验证集与测试集的实例与衰落哈希，由 `tests/test_frozen_scenario_v2.py` 守护。协议 v1 保持冻结，其结果不受影响。

本协议规定场景 v2.0（[规范](scenario-v2.md)）上所有实验共同遵守的实例划分、执行与衰落种子、评估口径和统计方法。与 v1 的主要差别：目标是承载能力而非能耗；评估回合长 20,000 个时隙；每个实例执行 1 次；部署在不同 N 之间嵌套。

## 1. 实例划分

编号区间沿用协议 v1。场景 v2.0 使用新的拓扑种子基准（40,000,000）与相位种子基准（60,000,000），与 v1 的种子区间不重叠，所以 v2 的每个实例都与 v1 不同，v1 已读过的测试集与确认集 C1 在 v2 下都是新实例。

| 集合 | 编号区间 | 数量 | 用途 |
|---|---|---|---|
| 开发池 `dev` | 0–9,999 | 10,000 | 调试、量级检查、规则的初步扫描；结果不作为论文结论 |
| 验证集 `validation` | 10,000–10,063 | 64 | 规则按 N 校准、学习方法选模 |
| 测试集 `test` | 20,000–20,199 | 200 | 方法冻结后才评估 |
| 备用池 `reserve` | 30,000–39,999 | 10,000 | 测试集被反复查看时，从这里另取确认集 |
| 训练池 `train` | 1,000,000–1,999,999 | 1,000,000 | 训练时抽取的唯一来源 |

## 2. 嵌套部署

实例 i 的部署在不同 N 之间嵌套：N 个 UE 的部署恰好是任何更大部署的前 N 个 UE。
- 拓扑：UE 按顺序逐个抽取位置与阴影（含覆盖规则的重抽），使用同一个随机流；UE j 的类别为 j mod 3，只取决于 j，所以前 N 个 UE 的抽取与后面的 UE 无关。
- 相位：按 UE 顺序抽取。
- 衰落与执行随机数：每个 UE 一个种子，由 `SeedSequence([基准, 集合编码, 实例, 执行序号]).spawn(N)` 的第 j 个子序列给出，与 N 无关。

嵌套的作用：同一实例在不同 N 下是"同一个部署再加入 UE"，F(N) 各点使用公共随机数，差异只来自新增的 UE；可选的 LP 正交上界的 s\* 随 N 单调不减，可以二分查找。

## 4. 评估

- 每个实例执行 1 次（dev、验证集、测试集都是如此），每个回合跑满 H = 20,200 个时隙。
- N 网格：方法与本地规则 {2, 4, 6, 8, 10, 12, 16, 20, 24, 28, 32}；N_EDF 另算 36、40（场景规范 §6）。
- 回合的指标、可行判据、不可送达包与承载能力的判定见场景规范 §5：主要 ε = 0.01，对照 ε = 0.05；F(N) 第一次低于 0.95 前的网格点为 N\*。
- 置信区间：两层 bootstrap（训练种子，再实例），10,000 次，种子 20,260,930；N\* 的分布在各 N 之间联合重抽训练种子与实例。规则与中央参照只有实例一层。
- 代码：`capacity.run_capacity_episode`、`capacity.summarize`；命令行 `evaluate_capacity`（方法）与 `evaluate_capacity_bounds`（LP 上界）。
- **补充（2026-10-04，用户批准；不改任何冻结数值）**：学习方法按 N 分别训练与评价。
  - **评价对象**：一种算法，即固定的训练流程与超参数，在每个 N 上各有一个实例。F(N) 是该算法在 N 上的实例的可行比例；N\* 的判定规则不变。
  - **允许的按 N 选择**：只能在预先登记的选择集上按 N 选择检查点，不能按 N 调超参数。本地规则按 N 在预先写定的参数表中选择，两者口径对应。
  - **训练的 N**：{2, 4, 6, 8, 10, 12, 16, 20}。N ≥ 24 用 N = 20 的模型评估，只作描述，不进入 ε = 0.01 的主要判读。
  - **部署假设**：N 在配置时已知，与按 N 校准的本地规则相同。Actor 的输入与运行时观测不变。
  - **混合 N 训练**：仍是允许的训练方式。用作对照时，其检查点同样按 N 选择。
  - **跨 N 泛化**：不再要求，列为后续工作，不在主要判读中报告。
  - **bootstrap**：训练种子 s 在各 N 上的实例组成一个"种子层"，与原口径相同，在各 N 之间联合重抽训练种子与实例。
  - **已有结果**：EXP-006 与 EXP-008 的结果属于"跨 N 单一策略"口径，结论不变，引用时注明。

## 5. 参照与基线

- 主中央参照为 N_EDF（集中式因果调度，场景规范 §7），与方法用同样的回合评估。
- **补充（2026-10-09，用户批准；不改任何冻结数值）**：配置授权基线 N_CG（[设计](../experiment-designs/configured-grant-baseline_20261009.md)，场景规范 §7）作为部署中的半静态参照。
  - 与 N_EDF 一样按回合评估，只有实例一层；
  - 没有参数，不需要校准；
  - 从 EXP-011 起，每份报告的主表在 N_EDF 与本地规则之外列入 N_CG 的 F(N) 与 N\*。
- **补充（2026-10-10，用户批准；不改任何冻结数值）**：N_CG 的分配改为优化的静态配置 CG-opt（[设计](../experiment-designs/configured-grant-optimized_20261010.md)）。
  - 仍按回合评估，只有实例一层；
  - 没有训练参数；求解预算（节点上限、评估上限）在第 0 阶段只用开发实例 0–63 的分配指标标定，之后冻结；
  - 从 EXP-011 起主表的 N_CG 采用 CG-opt，贪心 CG 作为描述性结果保留。
- LP 上界（N_UB、N_orth）不是任何实验的前置条件（用户决定，2026-10-01）：完整 LP 每个实例约 2 小时单核，成本超过它对下一步决策的帮助。需要讨论"距离理论上限多远"时，作为可选的离线分析在部分实例上计算（优先用合并子信道的松弛 `orth_agg`），计算时不运行任何方法。
- 本地规则在验证集上按每个 N 分别校准，每类规则单独选参数。校准后的参数在任何测试评估之前冻结并存档。
  - 选择规则（场景规范 §8）：
    1. 取 F_{0.01} 最高者；
    2. 相同时取 F_{0.05} 较高者；
    3. 再相同时取每回合最差 UE 违约率的均值较低者；
    4. 再相同时取下表中靠前者。
  - 参数表（2026-10-01 预先写定，依据开发实例上的初步扫描，见[第 0 阶段报告](../results/v2-phase0_20260930/report.md) §4）：

| 规则 | 参数（按表中顺序） | 个数 |

| sticky_max | 无 | 1 |
| p_persistent | a ∈ {2, 4, 8, 16, 32, 64} | 6 |
| opportunistic | θ ∈ {1, 1.5, 2, 3, 4}，补充 {0.5, 0.75} | 5 + 2 |
| reservation | (offset, failures) ∈ {(0.25, 1), (0.25, 2), (0.25, 4), (0.5, 1), (0.5, 2), (0.5, 4)} | 6 |

- N_EDF（规范版）与诊断用的 `defer_hopeless` 版也在验证集上评估，作为校准结果的参照。
- 每份报告的主表必须包含：同一网格上的 N_EDF 与全部本地规则的 F(N) 和 N\*；算过 LP 上界时一并列出，并注明所用实例。

## 6. 纪律与变更
