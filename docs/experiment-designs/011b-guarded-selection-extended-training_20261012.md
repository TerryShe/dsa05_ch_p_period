# EXP-DSA05-011B：防饿死选模与延长训练下的紧迫摘要复验

状态：**已定稿（2026-10-12，用户批准；第 1 版）**。§9 记录定稿时用户确认的 5 项决定（全部按建议）。

- 第 0 阶段已实现，并在关口 0 经用户确认（2026-10-12，§10）；阶段 1 已启动。

- 本实验是 EXP-011 之后的开发阶段实验，起因是 RES-DSA05-EXP011 的两个发现：
  - U 的一个检查点会饿死离 AP 最近的 UE，选模规则没有拦住它（报告 §6.1–§6.2）；
  - O、L、U₀ 的学习曲线在 500 万时隙时还在下降（报告 §7）。
- 按用户要求，**实验分阶段执行，每个阶段结束后暂停，与用户一起分析，经用户同意才进入下一阶段**（§6）。
- EXP-011 的判定（"无证据"）不变。本实验在新的开发切片上复验同一组假设，结论仍是开发阶段的依据；正式结论来自协议修订后对 v2-confirm1 的一次读取。

## 1. 问题

### 1.1 EXP-011 留下的问题

| 问题 | EXP-011 的证据 | 本实验怎样回答 |
|---|---|---|
| Q1：近 AP UE 被饿死是 U 特有的，还是学习流程的普遍问题？出现在哪些种子与训练阶段？ | 19 个灾难单元全部来自 U 种子 101 的 5M 检查点；M、M+Y、O、L、U₀ 为 0。选模集上近 UE 部署太少（每个 N 0–6 个） | 阶段 1：在近 UE 压力集上扫描全部已有检查点（§3.1） |
| Q2：拦住饿死的检查点之后，U 是否显著优于 M？ | 事后去掉种子 101，U − M 在 N = 8、10、12 都显著；但这是看过结果后的剔除 | 防饿死选模（§3.3），在新的评估切片上按原主判据复验（§5.2） |
| Q3：同等的更长训练下，U 是否仍优于 O、L（内容是否有价值）？ | 事后去掉种子 101，U 对 O、L 好 23–33%，都显著；但 O、L、U₀ 未收敛 | 所有学习方法同等延长到 10M（§3.2），U − O、U − L 升为预先写定的次要判据 |
| Q4：学习的响应是否优于手写让路规则？ | U − M+Y 不显著（事后去掉种子 101 也只好 11–14%） | 保留为次要判据，并预先写明检验力有限（§5.3） |

### 1.2 不在本实验中回答的

- 接收门限网格（H-B1）：EXP-011 已给出 M+Y 与 U 的门限边界，本实验只保留 U₀ 与 U@0 dB 的比较。
- XR-SBPC（H-S3、H-S4）：EXP-012。
- 训练端的修复（例如近 AP UE 过采样、特征截断）：只有阶段 1 发现饿死普遍存在时才需要，届时另写修正（§6，关口 A）。

## 2. 方法

### 2.1 方法与训练

| 名称 | 信息 | 来源 |
|---|---|---|
| **U** | L0 + L1 紧迫，−10 dB | EXP-011 的 3 个运行续训到 10M；另加种子 404、505（§9 第 1 项） |
| M | L0 | EXP-009 S1 的 3 个运行（`outputs/exp009-step2/s1-seed{101,202}`、`outputs/exp009-final/s1-seed303`）续训到 10M；另加种子 404、505 |
| M+Y | L0 + L1 紧迫 | 新选出的 M 加让路规则，−10 dB，不训练 |
| O、L | L0 + L1 占用 / 学习的消息 | EXP-011 的运行续训到 10M；另加种子 404、505 |
| U₀ | L0 + L1 紧迫，0 dB | EXP-011 的运行续训到 10M；另加种子 404、505 |
| U∅、U−N | U 的隐去消融 | 评估时，不训练 |
| U@0 dB | 在 −10 dB 下训练的 U 放到 0 dB 下评估 | 只用于与 U₀ 比较 |
| best_local、CG-opt、N_EDF | 参照 | 不训练 |

- L1 的定义、接收模型 R1、让路规则与 EXP-011 §2、§3.1 完全相同。
- 不再评估：接收门限网格、U−U（EXP-011 中与 U 几乎相同）、best_local+Y、M_exp009。

### 2.2 续训（§9 第 2 项）

- **所有学习方法同一流程**：先按原配方训练到 5M，再从 5M 检查点续训到 10M，每 100 万时隙一个检查点（6M–10M）。
  - 已有的运行直接续训；新增的种子 404、505 先按原配方训练 5M（U、O、L、U₀ 用 `configs/exp011-*.toml`，M 用 `configs/exp009-step2-s1.toml`），再续训。这样每个种子走完全相同的流程。
- **续训不改变训练状态**：
  - 检查点中保存了网络、优化器、采样器与随机数状态，全部恢复；
  - 熵系数在前 2.5M 时隙内线性降到 0，之后保持 0；学习率是常数。所以 5M 之后的续训，就是原训练平稳阶段的延续。
  - 配置中把预算改为 10M、熵衰减比例改为 0.25，使熵系数的时间表与原来逐时隙相同，由测试核对。
- **唯一的区别**：续训开始时各环境从新的回合开始；检查点不保存进行中的回合。这对所有运行都一样。
- 续训运行的清单记录源检查点的路径与 sha256。

### 2.3 近 UE 压力集与"饿死"的定义

- **压力集 exp011b-stress**：
  - 开发池 7,000–9,999 整段保留给压力集。只读取其中满足条件的部署：前 N 个 UE 中至少有一个距 AP < 5 m。
  - N ∈ {8, 12, 16}。按 exp011-eval512 的比例（2.5%、3.3%、4.9%），预计约 75、100、145 个部署。实际清单在第 0 阶段生成，与摘要一起登记。
  - 部署的 UE 位置在各 N 间嵌套（第 0 阶段核对过：同一实例前 N 个 UE 的位置与 N 无关）。
  - 只用于选模（§3.3）与阶段 1 的诊断，不用于评估。
- **饿死单元**：某个（检查点, N, 部署）中，有 UE 的平均信噪比 ≥ 20 dB（最大功率、最好的平均子信道；定义同 `diagnose_exp011.snr_bins`），而违约率 ≥ 0.5。
  - 依据：EXP-011 中被饿死的 UE 都在 3.7 m 以内。N = 8、10、12 的诊断中，M 与 M+Y 没有 ≥ 20 dB 的 UE 违约率超过 0.01；M、M+Y、O、L、U₀ 在所有 N 上都没有距 AP < 4 m 的 UE 违约率 ≥ 0.5。
  - 门限是看过 EXP-011 的失败后定的，如实记录。它只用于选模数据，评估切片是随机的、不经筛选的。

## 3. 阶段

### 3.1 阶段 1：饿死诊断（只用已有检查点，不训练）

- **扫描**：
  - 全部已有检查点（M、U、O、L、U₀ 各 3 个种子 × 1M–5M，共 75 个），在压力集的 3 个 N 上各运行一次；
  - exp009-screen256 上已有的逐回合结果，按同一定义重新统计饿死单元，不需要新的运行。
- **输出**：
  - 每个（条件, 种子, 检查点）的饿死单元数，按 N 分开；
  - 饿死是否随训练步数增加；
  - 被饿死的 UE 的距离、阴影与 RSSI 余量。
- **特征层面的反事实**（描述性）：对被饿死的 UE，取记录下的观测，把与自身信道增益有关的输入（自身增益以及由它算出的量）按 −10、−20、−30 dB 缩放，看 Actor 关闭的概率是否随之下降。用于判断问题是否来自训练中少见的极端增益。

### 3.2 阶段 2：续训

- 按 §2.2 续训已有的 15 个运行，并训练 10 个新运行（5 个学习条件 × 种子 404、505：先 0 → 5M，再续训到 10M），共 25 个运行，每个 10M。
- 不在看到筛选或评估结果后修改任何训练设置。

### 3.3 阶段 3：筛选与防饿死选模

- **筛选**：
  - 6M–10M 的新检查点在 exp009-screen256 上运行，网格同 EXP-011：U、O、L、M 在 N ∈ {6, 8, 10, 12, 16}，U₀ 在 N ∈ {8, 10, 12}；
  - 1M–5M 沿用已有结果；
  - 6M–10M 的新检查点在压力集上运行；1M–5M 已在阶段 1 运行；
  - 新种子 404、505 的全部检查点（1M–10M）在 exp009-screen256 与压力集上运行。
- **防饿死**：
  - 一个检查点若在压力集或 exp009-screen256 的**任何一个 N** 上有饿死单元，就在**所有 N** 上不入选。
  - 依据：混合 N 训练得到的是同一个网络，EXP-011 中种子 101 的 5M 检查点在 N = 6、8、12、16 上都饿死了近 UE。
- **选模规则**：
  - 每个（条件, 种子, N）在通过防饿死的检查点（1M–10M）中，选 exp009-screen256 上 P2 最低者；
  - 相同时取 F_{0.01} 较高者，再相同取较晚的检查点（同 EXP-011 §4.1）。
- **兜底**：若某个（条件, 种子）没有任何检查点通过，选饿死单元最少者，再按 P2 选，并在报告中单列。
- **预算效应**（描述性）：每个条件，候选限于 ≤ 5M 与 ≤ 10M 时选出的检查点，在 exp009-screen256 上的 P2 之差。

### 3.4 阶段 4：评估、诊断与分析

- **评估集 exp011b-eval512**：开发池 6,000–6,511，512 个部署，N ∈ {6, 8, 10, 12, 16}，每个部署 1 次执行。
  - 起草时核查：已登记的筛选集与评估集都不含 6,000–9,999。
  - 不经筛选，含近 UE 的部署按自然比例出现。
- **评估的方法**：
  - M、U、M+Y、O、L、U∅、U−N，在 5 个 N 上；
  - U₀ 与 U@0 dB，在 N ∈ {8, 10, 12} 上；
  - best_local、CG-opt、N_EDF，在 5 个 N 上。
- **诊断**：U、M、M+Y 在 N = 8、10、12 上，定义同 EXP-011 §5.3 第 7 项；另统计每个方法在评估集上的饿死单元。
- **分析**：按 §5 预先写定的规则。

## 5. 指标与判据

### 5.1 指标

- 同 EXP-011 §5.1：
  - 首要指标 P2；
  - 服务达标 F_{0.01} 与 N\*；
  - 敏感性：p90、去掉对所有方法都不可行的部署、log₁₀(w + δ)；
  - 全部 UE 的平均违约率；
  - 两层 bootstrap，10,000 次，种子 20,260,930。
- 新增：每个方法在 exp011b-eval512 上的饿死单元数（§2.3 的定义）。

### 5.2 主判据（同 EXP-011 §5.2）

- D_N = P2(U) − P2(M)，N ∈ {8, 10, 12}。
  - **有效**：三个 N 上的 95% 区间上限都 < 0；
  - **部分有效**：一个或两个；
  - **无证据**：没有。
- 若某个 N 上 U 显著变差（区间下限 > 0），单列讨论。

### 5.3 次要判据（预先写定解释，不改变主判据）

1. **内容（H-S2，本实验的重点）**：U − O、U − L，N ∈ {8, 10, 12}。
   - 对每个对照分别判定：三个 N 中至少两个区间上限 < 0，记为"U 优于该对照"。
   - U 同时优于 O 与 L：支持"相同比特预算下，紧迫内容优于占用感知与学习的消息"。
   - L 的解释仍不对称（EXP-011 §3.4）：L 不如 U，只说明这一训练预算下没有学到更好的内容。
2. **用法**：E_N = P2(U) − P2(M+Y)。
   - 三个 N 中至少两个区间上限 < 0：学习的响应优于手写规则。
   - 否则报告"未检出差别"。
   - **预先说明检验力有限**：EXP-011 中去掉种子 101 后，差别约 10–15%，区间半宽约为差别的 2–3 倍，大概率不显著。不显著不等于等价。
3. **饿死**：U 在 exp011b-eval512 上的饿死单元应为 0。若不为 0，说明防饿死选模没有拦住，如实报告。
4. **机制（H-M1、H-M2）**：同 EXP-011 §5.3 第 3 项（U∅、U−N）。
5. **0 dB**：U₀ − M 与 U₀ − U@0 dB，解释同 EXP-011 §5.3 第 4 项。
6. **负载**：N = 6–16 上的 D_N。
7. **预算效应与跨切片对照**（描述性）：
   - §3.3 的预算效应；
   - 主统计量在 exp011-eval512 与 exp011b-eval512 上的对照。

### 5.4 提出的方法（§9 第 5 项）

- **U 作为提出的方法**，须同时满足：
  1. 主判据至少"部分有效"；
  2. U 在评估集上的饿死单元为 0；
  3. E_N 不在两个以上的 N 上显著 > 0（即 U 没有显著劣于 M+Y）。
- M+Y 作为规则对照，与 U 一起进入最终确认。最终确认的具体比较在协议修订时写定。
- 若条件不满足，不自动改用 M+Y。与用户一起重新讨论核心表述。

## 7. 风险与局限

- **同时改了几件事**（防饿死、延长训练、新切片）：U 若通过，不能完全归因到某一项。§3.3 的预算效应部分回答这个问题。
- **防饿死与压力集是看过 EXP-011 的失败后加的**：作为开发过程是正当的，但论文中须写明这一流程是在诊断出失效模式后加入的。
- **第二次检验同一组假设**：评估切片是新的，但种子 101、202、303 的 1M–5M 检查点不变，阶段 1 也已在压力集上看过它们。最终结论仍以 v2-confirm1 为准。
- **U 对 M+Y 的检验力有限**（§5.3 第 2 项）。
- **续训与不中断的 10M 训练不完全相同**（§2.2），但所有方法、所有种子一样。
- **M 的检查点来自 EXP-009 时的提交**：续训用当前代码；L0 路径的前向计算在 EXP-011 第 0 阶段已核对与旧版逐位相同，续训前再用测试核对一次。
- **网页工具的影响**（§8.3）。
