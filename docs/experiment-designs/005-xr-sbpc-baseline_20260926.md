# EXP-DSA05-005：与 XR-SBPC 的正面比较

状态：**已定稿**（第 3 版）。2026-09-27 用户确认 §7 的七项决定，进入第 0 阶段（实现与验收）。

## 修改记录

**第 2 版（2026-09-27，按用户审阅意见）**：
1. V2 与 A 的比较不能解释为"只比较学习器"：两者同时改变了学习算法、网络结构、价值函数、经验回放和探索方式，比较的是两套完整训练方案（§2.4）。
2. 原文只存储有包 UE 的转移，但包完成后的下一状态是空闲状态，Q 值会从从未训练过的空闲状态自举。改为存入空闲转移，并屏蔽其 Actor 与温度更新（§2.1）。
3. 原文中途奖励迁移到 DSA05 后尺度失衡。第 2 版为此加入了截顶变体 V1c，第 3 版已将其替换，见下。
4. 主比较改用备用池中新取的确认集，不再使用已被查看过的 EXP-DSA05-004 测试集，也不再"只在结果有利于新基线时才启用备用集"（§3.2）。

**第 3 版（2026-09-27，按用户审阅意见）**：
1. **V1c 替换为 V1s**。V1c 只截顶单个时隙的中途奖励，但中途奖励按时隙累加，只要不完成就能继续领奖，拖延完成的激励仍然存在。所以 V1c 不能称为修正了奖励套利。V1s 去掉中途奖励，只保留原文的完成奖励与过期惩罚，是唯一真正消除拖延激励的变体（§2.2、§2.3）。
2. **Q1 预先指定共同的 γ = 0.99**。各变体各自选 γ 时，奖励与折扣因子同时改变，不能把差别严格归因于奖励。Q1 的主分析固定 γ = 0.99，γ = 0.5 作敏感性分析；各自调 γ 的结果只作为"调参后的实际表现"报告（§4）。
3. **训练改为全因子**：3 个变体 × γ ∈ {0.5, 0.99} × 3 个种子，共 18 个运行，一轮并行完成（§3.1）。
4. **诊断**改为能同时抓住"缓慢拖延"与"分块不完成"的四项逐包指标（§3.3）。

## 1. 动机与问题

[XR-SBPC](../../papers/XR-SBPC-WCNC2025/analysis.md)（Bagherinejad 等，IEEE WCNC 2025）是目前找到的与 DSA05 问题结构最接近的工作（见[问题侧笔记](../research/literature-problem-side_20260926.md) §2）：
- 带偏移的周期到达；
- 时延预算内按 Shannon 速率跨时隙累积服务；
- OFF 加子频带加离散功率的联合动作；
- 分布式执行的深度强化学习（SAC-Discrete，共享网络与经验池）。

审稿人很可能要求与它直接比较。本实验在 DSA05 环境中回答三个问题：

- **Q1（奖励）**：在同一个 SAC 训练方案、同一个 γ 下，XR-SBPC 式的可靠性奖励（有塑形的 V1、无塑形的 V1s）与我们的能耗加违约惩罚奖励（V2）相比，可行性和能耗有何差别？
- **Q2（完整方案）**：在相同奖励、相同执行时信息下，XR-SBPC 式的完整训练方案（V2）与我们的约束式循环 MAPPO（A）相比如何？两者的差别见 §2.4，结论只能归于整套方案，不能归于其中任何一个组成部分。
- **Q3（塑形的作用）**：原文奖励中的中途塑形项迁移到 DSA05 后，是否驱动了拖延完成或分块不完成的行为？（V1 对 V1s，结合 §3.3 的诊断）

只在 DSA05 的环境中比较，不把我们的方法搬到 XR-SBPC 的体内子网场景：那是下行干扰网络、目标是可靠性，问题不同。

## 2. 被比较的方法

所有 SAC 变体都在 DSA05 v1.0 场景、协议 v1 下训练，与 EXP-DSA05-001 长训使用同样的训练实例池、回合结构（每回合 600 时隙，截断时自举）和验证流程。

### 2.1 共同部分：SAC-Discrete 训练方案

| 项目 | 取值 | 依据 |
|---|---|---|
| 算法 | SAC-Discrete：策略网络、两个 Q 网络及各自的目标网络，自动调节温度 | 原文 §IV-B |
| 参数共享 | 所有 UE 共用策略网络和 Q 网络，所有 UE 的转移进入同一个经验池；Q 函数只以本 UE 的局部观测为输入 | 原文 §IV-B |
| 网络 | 前馈网络，隐藏层 400/300/200/100；前三层 LeakyReLU，最后一层 Tanh；策略输出 softmax，Q 输出无激活 | 原文 §V-A。原文对各层激活函数的描述有歧义，这是我们的解读 |
| 学习率 | 1e-4（三个网络相同） | 原文 §V-A |
| 批大小 | 512 | 原文 §V-A |
| 经验池 | 容量 10,000 条转移；池满后开始更新 | 原文 §V-A、算法 1 |
| 优先经验回放 | 比例型，α=0.6，β 从 0.4 线性增至 1，新转移取当前最大优先级 | 原文采用优先经验回放但未给参数，这里用 Schaul 等的默认值 |
| 目标网络软更新 | τ = 0.005 | 原文 §V-A |
| 目标熵 | 0.05（常数），初始温度 1 | 原文 §V-A、算法 1 |
| 折扣因子 | γ ∈ {0.5, 0.99}，全因子训练，见 §3.1 | 0.5 为原文取值，0.99 为 A 的取值 |
| 合法动作 | 无包的 UE 只能选 OFF（与 A 的 Actor 相同的掩码）；策略分布、目标值中的期望都只在合法动作上计算 | 原文算法 1 强制空闲 UE 选 OFF |
| **空闲转移** | **每个时隙存入所有 UE 的转移，包括无包的 UE。Q 损失对全部转移计算；Actor 损失与温度损失只对当前状态有两个以上合法动作（即有包）的转移计算** | **偏离原文**，见下 |
| 更新频率 | 16 个并行环境每前进一个时隙，做一次梯度更新；2000 万时隙共 125 万次 | 原文每步一次；我们按环境步计 |
| 预算 | 2000 万时隙，与 EXP-DSA05-001 长训相同 | 与我们的方法同预算 |
| 执行 | 从策略分布中随机采样，使用协议冻结的逐 UE 执行种子 | 与我们的方法评估方式相同 |

**为什么偏离原文的空闲转移处理**：原文只存储有包 UE 的转移。但包在某个时隙完成（或过期）后，该 UE 的下一状态是空闲状态，它的目标值 r + γ·V(s′) 要从空闲状态自举。按原文字面实现，空闲状态的 Q 值从未被训练，自举值是任意的，这会让"完成包"这类最关键的转移得到错误的目标。V2 的团队奖励在空闲期间仍然非零（其他 UE 的能耗与违约），问题更明显。原文没有说明如何处理，所以统一改为：存入空闲转移，只训练它的 Q 值，不让它影响策略和温度。空闲状态只有 OFF 一个合法动作，策略熵为 0，其目标值为 r + γ·min_j Q′_j(s′, OFF)。

我们也考虑过另一种做法：把空闲期合并成一个多时隙转移，累积折扣奖励，折扣取 γ 的空闲时长次方。它的实现与检验更复杂，所以不采用。

**观测（执行时信息与 A 的 Actor 一致）**：与 A 的 Actor 在同一时隙看到的特征完全相同。具体是 `LocalMemory.features` 的逐子信道特征（公共 RSSI、推断的干扰、上一时隙自己的发送、各功率档可提供的比特与每时隙所需比特之比）与上下文（有无包、剩余比特比例、距截止期比例、周期、上一时隙结果与服务量、增益估计、每时隙所需比特），展平成一个向量。其中"每时隙所需比特"就是原文的"目标吞吐"。

与原文的差别：
- 去掉原文的邻居上一帧动作和本链路即时信道增益，因为 DSA05 的信息结构中没有这些信息；
- 没有循环记忆，这是原文方法本身的设定。

### 2.2 三个变体

记 S 为 UE 在本时隙开始时的剩余比特，D 为距截止期的时隙数（含本时隙），R 为本时隙得到的互信息比特，φ = S / D 为原文的"目标吞吐"。

- **V1：原文奖励，字面迁移**。有包的 UE 得到逐智能体奖励（原文式 7），不含能耗项：
  - 本时隙完成解码（R ≥ S）：+α_s = +50；
  - 否则，若 D = 1（本时隙末过期）：−α_f = −100；
  - 否则，若 R ≥ φ：+α′_s · R/φ，α′_s = 5；
  - 否则：−α′_f = −10。

  空闲 UE 的奖励为 0（原文未定义，取 0）。原文 §V-A 写 α_f = −100，与式 7 要求的正系数矛盾，这里按式 7 的含义取失败惩罚 −100。

- **V1s：原文目标，去掉塑形**。只保留完成奖励与过期惩罚：
  - 本时隙完成解码：+50；
  - 本时隙末过期：−100；
  - 其他时隙（包括空闲）：0。

  这对应原文的优化目标（式 5a，最大化按时完成的包数）以及原文完成、失败两项的数值，去掉了两项中途塑形。它的奖励稀疏，要靠折扣回报把完成奖励传回前面的时隙。

- **V2：同一 SAC 方案 + 我们的奖励**。奖励与 A 完全相同：团队奖励 r_t = −(Σ_i E_i(t)/E0 + w Σ_i c_i(t))/N，w = 10，E0 = τ·p_max，c_i(t) 为 UE i 在时隙 t 末的违约指示。每个 UE 的转移（包括空闲 UE）都记这同一个团队奖励。

### 2.3 V1 的中途塑形为什么在 DSA05 中造成拖延激励

中途奖励按时隙累加，只要不完成就能继续领取。
- 例如一个 D = 40 的包，若每个时隙恰好传输 R = φ，前 39 个时隙各得 +5，最后完成得 +50，未折扣总奖励 245，远高于立即完成的 +50。
- 未完成时 R < S，所以 R/φ = R·D/S < D，单个时隙的中途奖励最高可接近 5 × 40 = 200。

在 DSA05 中这种激励可以被利用：
- 三类业务的目标吞吐在到达时都是 614.4 比特/时隙（6144/10、12288/20、24576/40）；
- 在 5 dBm、无干扰时，一个时隙能服务的比特数，在 dev 实例（0–99，N = 8，共 800 个 UE）上的中位数为：0–50 m 约 3,480，50–75 m 约 930，75–100 m 约 340；
- 中远端 UE 的单时隙服务量与 φ 相当，可以"慢慢拖到截止期"；
- 近端 UE 最低功率下也至少是 φ 的数倍，拖延表现为"分几块发、每块都不完成"。

原文场景中包很大，要好几帧才能发完。按原文参数粗略估计（平均包约 750 kbit；按 20 dB 的 SINR，每个子频带每帧约 130 kbit；时延预算 10–15 帧），R/φ 通常只有 1–2，完成奖励占主导。这是我们的估计，原文没有给出。

V1 保留原文奖励的字面形式，用来如实展示迁移后的行为；V1s 用来检验这种行为是否由塑形项驱动（Q3）。

### 2.4 V2 与 A 的差别（Q2 的解释范围）

两者奖励相同，执行时每个 UE 能用的信息相同，但训练方案在以下各方面同时不同，所以 V2 对 A 的比较只能解释为两套完整训练方案的比较：

| 方面 | V2（XR-SBPC 式） | A（EXP-DSA05-001） |
|---|---|---|
| 学习算法 | 离策略 SAC-Discrete | 同策略 PPO |
| 策略网络 | 前馈，无记忆 | 逐子信道共享 GRU 加 DeepSets，有记忆 |
| 价值函数 | 逐智能体 Q，只以本 UE 局部观测为输入 | 集中式状态价值 Critic，训练时使用全局状态（含真实增益） |
| 经验回放 | 优先经验回放 | 无，按轨迹做 GAE |
| 探索 | 自动温度，目标熵 0.05 | 熵系数 0.01，在前 1000 万时隙线性降到 0 |
| 折扣 | Q2 主分析为调参后选定的 γ；补充分析为 0.99 | 0.99 |

## 3. 实验

### 3.1 训练（全因子）

- **场景**：N = 8（`configs/scenario-v1-n8.toml`）。先只做 N = 8；是否扩展到 N = 12，看结果后另行决定。
- **运行矩阵**：3 个变体（V1、V1s、V2）× γ ∈ {0.5, 0.99} × 种子 {101, 202, 303}，共 18 个运行，一轮并行。每个运行 2000 万时隙，每 100 万时隙用 64 个验证实例验证一次。
- **选检查点**：每个运行按协议规则在验证集上选出候选，同时保留最后检查点。
- **调参后的设置**：每个变体只看种子 101 的两个运行，把两个 γ 的全部验证候选合在一起，按协议规则选出一个 γ。该变体"调参后的实际表现"用这个 γ 的 3 个种子。这一选择只用于 §4 第 5、6 条，不影响 Q1 主分析。

### 3.2 确认集

EXP-DSA05-004 的测试集结果已经被查看过。按 [MARL 实验协议 v1](../research/marl-protocol-v1.md) §7 的规定（如果开发中查看了测试集，需在备用池中另取确认集），本实验的所有正式比较在备用池中新取的确认集上进行，**不论结果对哪一方有利**：

- **确认集 C1**：备用池的实例 30,000–30,199，共 200 个，每个实例执行 2 次；执行种子沿用协议的公式 SeedSequence([20260925, 3, N, 实例, 执行次序])，其中 3 是备用池的编号。
- **参照**：在任何方法评估 C1 之前，先用与协议 v1 参照相同的流程，计算 C1 上 N = 8 的逐实例上下界，形成正式记录。
- **评估对象**：
  - A 与 C 的冻结长训运行（EXP-DSA05-001 第 2b 阶段）：各 3 个种子，选中与最后检查点；
  - 全部 18 个 SAC 运行：选中与最后检查点；
  - 本地基线：参照 paced_sticky（margin = 0.5），以及 random_max、sticky_max、lazy_pacing。
- **顺序**：本设计定稿后，先完成 C1 的参照与评估代码，再训练、选模；18 个运行全部选模完成、评估代码提交之后，才在 C1 上评估一次。
- **与 EXP-DSA05-004 的关系**：EXP-DSA05-004 的测试结果保持不变，本实验不再使用测试集。A、C 与基线在 C1 上的结果同时构成对 EXP-DSA05-004 结论的一次独立复验，报告中并列给出。
- **之后的确认集**：若日后据本实验改进方法，最终比较使用备用池中下一段未用的实例（30,200 起），届时另写计划。

### 3.3 行为诊断（描述性）

在 64 个验证实例上重放各运行的选中检查点，与 EXP-DSA05-001 的诊断方式相同。对 A、V1、V1s、V2 都计算：

1. **每包发送时隙数**；
2. **完成时刻占截止期的比例**，即（完成时隙 − 到达时隙）/ 周期；过期的包单独统计；
3. **每包累计中途奖励**：按 V1 的塑形公式计算，对所有方法都算，以便比较；
4. **未完成时隙中 R/φ 的分布**。

另外沿用 EXP-DSA05-001 的功率档占比、能耗/下界、冲突率与干扰损失。前两项刻画"缓慢拖延"，后两项刻画"分块不完成"。

**解读注意**：对 DSA05 的能耗目标，低功率、摊开发送本来就是节能的行为，中央最优解就是这样。所以不能单凭"发送时隙多、完成晚"判定为套利。V1 套利的特征是：多时隙发送的同时 R/φ 偏高、功率档不低、能耗高。A 摊开发送时应以低功率档为主。

## 4. 预先写定的判读（全部在 C1 上）

区间与 EXP-DSA05-004 相同：两层 bootstrap（训练种子 × 实例，10,000 次，种子 20260926）。所有配对比较都逐实例配对，使用选中检查点；最后检查点的结果单独列出，只作描述。

1. **满足约束**：每个方法 C1 上 F ≥ 0.95。
2. **与参照基线**（paced_sticky，margin = 0.5）：规则同 EXP-DSA05-004 §3 第 2 条。
3. **Q1 主分析（γ = 0.99）**：V1 − V2、V1s − V2、V1 − V1s 的能耗/上界之差及其区间，并报告三者的 F。
   - 结论写为"在同一 SAC 方案、γ = 0.99 下的奖励效应"；
   - 只有 V1 与 V1s 相对 V2 的差别方向一致时，才把差别归于"可靠性奖励与能耗奖励之别"；否则报告结论取决于是否使用中途塑形。
4. **Q1 敏感性分析（γ = 0.5）**：同样的三组比较。
   - 方向与主分析一致，称奖励效应对 γ 稳健；
   - 否则报告奖励效应依赖 γ；
   - 某个变体在 γ = 0.5 下学不起来（例如不可行），如实报告。
5. **调参后的实际表现**：每个变体用 §3.1 选定的 γ，报告 F、能耗/上界与区间。这是"各方案调参后的实际表现"，不作因果归因。
6. **Q2 主分析**：调参后的 V2 − A 的能耗/上界之差及其区间，只在两者都满足约束时判断：
   - 区间下限 > 0：A 的训练方案显著更好；
   - 区间上限 < 0：V2 的训练方案显著更好；
   - 区间包含 0：没有显著差异。

   结论只归于整套训练方案（§2.4），调参方式也属于方案的一部分。**Q2 补充**：γ = 0.99 的 V2 − A，去掉了 γ 这一项差别，但其余差别仍在，结论同样只归于整套方案。
7. **Q3（塑形的作用）**：V1 − V1s 的能耗/上界之差与 F 之差（即第 3 条中的同一比较），结合 §3.3 的诊断，描述性报告。
8. **复验 EXP-DSA05-004**：A、C 与基线在 C1 上按 EXP-DSA05-004 §3 的规则重新判读，与原测试集结论并列。

## 5. 风险与局限

- **不是原文复现**：原文参数有不一致，没有找到公开代码，还做了几处调整：信息条件匹配、空闲转移处理、V1s 去掉塑形。报告和论文中称为"按 XR-SBPC 的方法在 DSA05 中实现的基线"，并列出这些调整。
- **信息条件对原方法不利**：原文的观测包含邻居上一帧动作，这里去掉了。审稿人可能认为这削弱了基线，论文中需要说明。如有需要，可另做一个"信息更多"的敏感性变体，不在本设计范围内。
- **超参数的迁移**：经验池容量、目标熵等是在原文场景下选的，未必适合 DSA05；存入空闲转移后，经验池中有包转移的比例也会下降。我们只考察两个 γ，这可能低估基线，论文中如实说明。
- **稀疏奖励**：V1s 的奖励稀疏，γ = 0.5 时完成奖励几乎传不回前面的时隙，可能学不起来。这会如实报告，也是 Q1 主分析取 γ = 0.99 的原因之一。
- **γ = 0.99 放大 V1 的拖延激励**：塑形项累积得更多。这是奖励迁移问题的一部分，由 §3.3 的诊断刻画。Q1 主分析的结论明确限定在 γ = 0.99 下。
- **离策略方案的样本效率可能更高**：若 V2 学得更快或更好，这会影响论文方法部分的叙述，但不影响问题表述、中央参照与评价协议这几项主要贡献。
- **计算量**：18 个训练运行并行，每个 2000 万时隙，另加 125 万次批大小 512 的梯度更新。C1 的参照需要为 200 个实例求解中央上下界。耗时在第 0 阶段实测后再估计。

## 7. 已确认的决定（2026-09-27）

1. **三个变体**：V1（原文奖励，字面迁移）、V1s（仅完成奖励与过期惩罚）、V2（我们的团队奖励，w = 10），共用同一个 SAC-Discrete 方案。执行时信息与 A 的 Actor 一致，去掉原文的邻居动作与即时信道增益。
2. **空闲转移**：存入所有 UE 的转移，Q 损失全用，Actor 与温度损失只用有包的状态（§2.1）。
3. **超参数**：按 §2.1 的取值。
4. **运行矩阵**：N = 8，3 个变体 × γ ∈ {0.5, 0.99} × 3 个种子，共 18 个运行，每个 2000 万时隙，一轮并行。
5. **确认集**：所有正式比较在备用池的 C1（30,000–30,199，每个实例 2 次执行）上进行，A、C 与基线一并重新评估；不再使用 EXP-DSA05-004 的测试集。
6. **判读分层**：如 §4。Q1 主分析固定 γ = 0.99，γ = 0.5 为敏感性分析；各自调 γ 的结果只作"调参后的实际表现"；Q2 只解释为两套完整训练方案的比较。
7. **诊断**：§3.3 的四项逐包指标，对 A 与三个变体都计算。
