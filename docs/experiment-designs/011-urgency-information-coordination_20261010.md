## 1. 问题

### 1.1 要检验的假设（框架第 3 版 §4.4）

### 1.2 已有证据与本实验要补上的

- **探针**（RES-DSA05-PROBE-BROADCAST、RES-DSA05-PROBE-FLAGLOSS）：
  - 在不重新训练的策略上加 1 比特紧急标志与手写让路规则，三个 N、三组策略上 F 都提高；
  - 增益依赖"弱的紧急 UE 单独发送时，标志能被读到"：在 0 dB 门限下，N = 8 的增益基本消失。
- **探针没有回答的**：
  - 策略学会使用紧迫信息之后，增益是否更大；
  - 在写定的接收模型下增益还剩多少；
  - 增益是否真的来自让路；
  - 换成别的内容（占用、学到的消息），同样的比特预算是否一样有效。
- **文献**（literature-problem-side §2.4）：按紧迫性让路的原则不新，学习信令也不新。所以本实验除了主比较，还加了两个同预算的内容对照（§3.4），用来区分"紧迫性这一内容"与"多了几比特"。

## 2. L1 信息等级（场景补充，定稿时登记）

L0 方法的观测与执行完全不变。L1 只给本设计的 U、O、L、U₀ 四种方法，以及手写规则的 +Y 版本。

### 2.1 时序

- 时隙 t 内，每个发送的 UE 随数据附带 1 比特上行标志；AP 在时隙末尾读出标志。
- AP 按子信道汇总，得到 K 比特的广播 b(t)，在时隙 t + 1 开始时与公共 RSSI 一起下发，用于时隙 t + 1 的决策。
- 时延与现有 RSSI 广播相同：都是上一时隙的信息。

### 2.2 上行标志的内容（三种，比特预算相同）

| 内容 | 上行 1 比特 | 用途 |
|---|---|---|
| 紧迫（U） | 发送且 slack < 3 时为 1 | 提出的方法 |
| 占用（O） | 不需要上行比特；AP 检测到发送即视为 1 | 对照："看得见"是否就够 |
| 学习的消息（L） | 由策略的第二个输出头决定，只在发送时有效 | 对照：内容交给训练决定 |

- **slack** 的定义同第 0 步与探针，只用本地信息：slack = 距截止期的时隙数 − ⌈剩余比特 / r_max⌉。r_max 是自己最好的子信道上、无干扰、最大功率时的速率。
- 门限 3 沿用第 0 步，没有调，本实验也不调。
- **设计依据**（框架第 3 版 §4.3）：N_EDF 按松弛量排序分配子信道，一个 UE 不会拿走已分给更紧急 UE 的子信道。紧迫摘要把"这个子信道上有没有更紧急的人"压缩为绝对门限下的 1 比特，是这一排序信息的最粗近似。

### 2.3 接收模型 R1（预先写定）

- **读出条件**：AP 读到 UE i 在子信道 k 上的标志，当且仅当这次发送的 TIN SINR ≥ θ_f = −10 dB。
  - SINR 由 AP 报告的这次发送的互信息换算，与探针 B3s 的做法相同，只是门限不同。
  - 同信道的干扰已计入 SINR，所以碰撞中信号弱的一方会丢标志，强的一方可能保住。
- **为什么取 −10 dB**：标志可以用两条参考序列之一来表示 1 比特。约 100 个信道使用的序列有约 20 dB 的处理增益；1 比特的序列判决需要约 10 dB，所以读出门限约为 −10 dB。
- **简化**：
  - 不计虚警：没有发送标志时，AP 不会误读为 1；
  - 不计标志占用的资源：标志随数据所需的参考信号发送，场景的 Shannon 速率模型本来就不计参考信号开销。
- **不按结果选门限**：−10 dB 来自上面的物理估算，不来自探针结果，它是**主接收条件**：除 U₀ 外，训练、选模与主判据都只用它。
- 其他门限组成接收条件网格（§3.5），只用于解释收益的成立条件。

### 2.4 下行广播

- b_k(t) = 1，当且仅当时隙 t 在子信道 k 上至少有一个被读出的标志（占用内容下为至少一个被检测到的发送）。
- 下行广播无差错，与现有 RSSI 广播的假设相同。
- **自身歧义**：一个 UE 若上一时隙在子信道 k 上发送了标志，它无法区分 b_k = 1 是不是来自自己。
  - 学习方法在观测中额外得到"自己上一时隙发出的标志"，由网络自己处理；
  - 手写规则沿用探针的处理：若自己上一时隙在 k 上且发出了标志，忽略 b_k。

### 2.5 观测的改动

- 每个子信道的 token 加 1 项：b_k。
- 上下文加 1 项：自己上一时隙发出的上行比特（占用内容下恒为 0）。
- L 方法的 Actor 另加一个 2 值输出头（消息比特）。策略的联合对数概率为 log π(a) + 1[a ≠ OFF] · log π(m)，熵项同时计入两个头。
- 其余输入、网络结构与 21 个动作不变。集中训练的 Critic 读取各 UE 的 Actor 特征，自动包括新增的两项。

### 2.6 信息开销与 NR 对应

| 等级 | 下行（每时隙） | 上行 |
|---|---|---|
| L0 | K 个子信道的公共 RSSI、自己的发送结果（场景已有） | 无 |
| L0 + L1 | 另加 K = 4 比特 | 每次发送附带 1 比特（O 不需要） |

- NR 对应是类比，不是逐条实现：
  - 上行 1 比特对应高优先级 SR（Rel-16）一类的紧急指示；
  - 下行 K 比特对应组公共的上行取消指示（DCI 2_4）。
- 语义上有一个重要区别：DCI 2_4 要求被指示的低优先级传输**必须**取消；L1 的广播只是信息，是否让路由策略决定。手写规则 +Y（§3.1）强制不紧急的 UE 推迟，语义上最接近 DCI 2_4。
- 引用的 NR 条款已在第 0 阶段核对，见 §2.7。

### 2.7 NR 条款核对（第 0 阶段，2026-10-10）

| 条款 | 内容 | 来源 |
|---|---|---|
| TS 38.212 §7.3.1（表 7.3.1-1） | DCI format 2_4："Notifying a group of UEs of the PRB(s) and OFDM symbol(s) where UE cancels the corresponding UL transmission from the UE" | [itecspec 38.212 §7.3.1](https://itecspec.com/3gpp/38.212/s/7.3.1) |
| TS 38.213 §11.2A | 配置了 UplinkCancellation 的 UE 用 CI-RNTI 监听 DCI format 2_4；检测到后取消与指示资源重叠的 PUSCH 或 SRS；若另配置 uplinkCancellationPriority，只取消优先级 0 的 PUSCH | [itecspec 38.213 §11.2A](https://itecspec.com/3gpp/38.213/s/11.2a) |
| TS 38.331 SchedulingRequestResourceConfigExt-v1610 | `phy-PriorityIndex-r16 ENUMERATED {p0, p1}`：p0 为低优先级，p1 为高优先级（物理层的优先级处理与复用） | [itecspec 38.331](https://itecspec.com/3gpp/38.331/s/schedulingrequestresourceconfig) |

核对后，对应关系的写法：

- **下行**：K 比特广播对应 DCI format 2_4 这类组公共、按资源指示的信令。强制让路 +Y 对应"配置了 uplinkCancellationPriority 时只取消低优先级 PUSCH"。
- **上行**：1 比特标志对应 SR 的高、低优先级之分（p1 / p0）。区别是 NR 的 SR 在单独的 PUCCH 资源上请求调度，L1 的标志随数据发送。
- **时序上的区别**：NR 中 gNB 指示的是之后将被取消的资源（为已调度的高优先级传输让出）；L1 标记的是上一时隙紧急 UE 所在的子信道，相当于预测它会继续在那里发送。
- 以上读的是 itecspec 上的 Rel-19 文本（与 CG 设计 §3.7 相同的来源），没有逐字核对 Rel-16 原版。

## 3. 方法与比较

### 3.1 方法

| 名称 | 信息 | 协调方式 | 训练 |
|---|---|---|---|
| **U**（提出的方法） | L0 + L1 紧迫 | 学习对广播的响应 | 新训练，3 个种子 |
| M | L0 | 隐式（学习） | 已有（EXP-009 S1，3 个种子层） |
| M+Y | L0 + L1 紧迫 | M 加手写让路规则（不紧急的 UE 若所选子信道被标记，则本时隙推迟） | 不训练 |
| O | L0 + L1 占用 | 学习 | 新训练，3 个种子（§9 第 2 项） |
| L | L0 + L1 学习的消息 | 学习（消息内容也学习） | 新训练，3 个种子（§9 第 2 项） |
| U₀ | L0 + L1 紧迫，在 θ_f = 0 dB 下训练与评估 | 学习对广播的响应 | 新训练，3 个种子（§3.5、§9 第 3 项） |
| best_local、best_local+Y | L0；L0 + L1 紧迫 | 本地规则；本地规则加让路 | 不训练 |
| CG-opt | L2 | 静态独占 | 不训练 |
| N_EDF | L∞ | 集中调度 | 参照上限 |

- 让路规则 +Y 即探针的 B3 规则（推迟，不换信道），只把标志的读出条件换成 R1。
- A-mix 不在本实验中评估：本实验的问题是"同一流程下多一项信息"，M 是对应的 L0 方法。A-mix 留在最终确认的方法清单中。

### 3.2 训练（U、O、L、U₀）

- **流程与 M 逐项相同**（`configs/exp009-step2-s1.toml`）：
  - 混合 N 训练，14 个环境，N ∈ {4, 4, 6, 6, 8, 8, 10, 10, 12, 12, 16, 16, 20, 20}；
  - 静态困难分层采样（S1，冻结的 τ）；
  - 500 万个环境时隙，每 100 万时隙一个检查点；
  - 种子 101、202、303；超参数全部相同。
- 配置文件只在 [experiment] 与新增的 [information] 两节上与 M 不同，由测试核对。U₀ 与 U 只差读出门限。
- 不在看到筛选或评估结果后修改任何训练设置。若学习曲线在 500 万时隙时仍明显上升，如实报告，不在本实验内追加预算。

### 3.3 机制消融（只在评估时，不重新训练）

| 名称 | 改动 | 检验 |
|---|---|---|
| U∅ | 所有 UE 看到的广播都置为 0 | H-M2：去掉摘要后增益是否消失 |
| U−N | 只对本时隙不紧急的 UE 置 0 | H-M1：增益是否来自不紧急的 UE 让路 |
| U−U | 只对本时隙紧急的 UE 置 0 | H-M1 的对照：紧急 UE 自己是否也在利用广播 |

- "紧急"按 §2.2 的 slack 规则判定。
- 置 0 的广播是正常可能出现的观测（没有紧急 UE 时就是全 0），不是训练中没见过的输入。

### 3.4 内容对照

- **O 对 U**：O 告诉 UE "有人在那里"，包括 RSSI 上看不出的弱 UE（探针中，失败 UE 被进入的情况有 11%–24% 发生在 RSSI 超出噪声不到 3 dB 的子信道上）；U 告诉 UE "那里的人紧急"。
- **L 对 U**：内容交给训练决定。
  - 解释是不对称的：L 与 U 一样好或更好，说明"这个比特预算足够，内容可以学到"；
  - L 更差，只说明 PPO 在 500 万时隙内没有找到比紧迫性更好的内容，不说明不存在更好的内容。从零学习信令常常收敛不到有意义的协议，这是已知的困难。

### 3.5 接收条件测试（H-B1）

- **网格**（预先写定）：读出门限 θ_f ∈ {全部读到, −15, −10, −5, 0} dB。
  - "全部读到"同探针 B3，0 dB 同探针 B3s；
  - −10 dB 是主接收条件。
- **在网格上评估的方法**（只在 N ∈ {8, 10, 12} 上）：
  - **M+Y**：规则不需要训练，它在各门限下的结果直接给出规则版本的门限边界。
  - **U**：在 −10 dB 下训练的策略，放到其他门限下评估。它衡量的是训练好的策略对接收条件变化的稳健性，不是"在该门限下训练能得到的最好结果"。
  - **U₀**：在 0 dB 下训练，并只在 0 dB 下评估。它与 U 在 0 dB 下的结果相比，区分"训练与评估的接收条件不一致"和"0 dB 下摘要本身信息不够"。
- **门限边界**：对每个方法与每个 N，取网格中满足 P2(方法, θ) − P2(M) 的 95% 区间上限 < 0 的最大门限。
  - 不强制单调；网格上每一点的差值与区间都报告。
  - M 不读摘要，所以它的 P2 与门限无关。
- U、O、L 的训练与选模只用主接收条件；U₀ 的训练与选模都在 0 dB 下进行，选模规则同 §4.1。

## 4. 选模与评估集

### 4.1 选模：按 P2 选检查点（§9 第 5 项）

- 筛选集沿用 exp009-screen256（开发池 3,000–3,255），与 M、A-mix 当初选模的集合相同。
- **规则**：每个（方法，种子，N）在 5 个检查点中选 P2 的部署均值最低者；相同时取 F_{0.01} 较高者，再相同取较晚的检查点。
- **M 也按这条规则重新选**：M 的 15 个检查点在 exp009-screen256 上已有全部 N 的逐回合结果，重选不需要新的评估。
  - 原因：首要指标已改为 P2（框架第 2 版），而 EXP-009 是按 F_{0.01} 选的模；U 与 M 用同一规则才可比。
  - 重选后的 M 与 EXP-009 冻结清单中的 M 可能不同，报告中列出两者，并在协议修订中更新方法清单。
- 只在评估集的 N 上选：N ∈ {6, 8, 10, 12, 16}；U₀ 只在 N ∈ {8, 10, 12} 上选（它只用于 §3.5）。

### 4.2 评估集：exp011-eval512

- 开发池 5,000–5,511，512 个部署，N ∈ {6, 8, 10, 12, 16}，每个部署 1 次执行，种子同协议 v2（dev，种子代码 0）。
- 起草时核查：`outputs/` 与 `docs/` 中没有任何文件引用开发实例 5,000–9,999。定稿后按 EXP-010 的方式登记（机器清单、摘要、`--screen exp011-eval512 --formal`）。
- 只用于本实验的评估；不读任何确认集。

**为什么用这几个 N**（已读的 exp009-screen256 上，M 的 P2 部署均值，描述性）：

| N | 6 | 8 | 10 | 12 | 16 | 20 |
|---|---|---|---|---|---|---|
| P2 均值 | 0.0010 | 0.0021 | 0.0055 | 0.0116 | 0.098 | 0.65 |
| P2 = 0 的部署比例 | 0.77 | 0.62 | 0.35 | 0.13 | 0.00 | 0.00 |

- N = 6 时大部分部署的 P2 为 0，改善的余地很小；N = 16 时负载已很高。所以判据用中间的三个 N（§5.2），N = 6 与 16 只作描述。

## 5. 指标与判据

### 5.1 指标（框架 §5）

- **首要**：P2，每个部署的最差 UE 违约率 w = max_i V_i / M_i 的部署均值；方法间的配对差值，同时报告均值之比。
- **服务达标**：F_{0.01}，以及评估集各 N 上的 N\* 描述。
- **敏感性**：w 的 90% 分位；去掉对所有方法都不可行的部署后的均值；log₁₀(w + δ) 的均值，δ = 10⁻⁴（本实验暂取，协议修订时正式写定）。
- **防止牺牲其他 UE**：全部 UE 的平均违约率。
- **统计**：两层 bootstrap，部署在方法间配对，各方法的种子层各自重抽，10,000 次，种子 20,260,930（协议 v2）。

### 5.2 主判据（预先写定，§9 第 4 项）

主统计量：D_N = P2(U) − P2(M)，N ∈ {8, 10, 12}。

| 结果 | 条件 | 解释与下一步 |
|---|---|---|
| **有效** | 三个 N 上 D_N 的 95% 区间上限都 < 0 | 支持 H-S1（与 EXP-010 一起，支持"瓶颈在看不到别人的紧迫性"）。U 进入最终方法清单，接着做 EXP-012 与协议修订 |
| **部分有效** | 一个或两个 N 上区间上限 < 0 | 如实报告增益出现在哪些负载。是否以 U 作为提出的方法，由用户根据 §5.3 的结果决定 |
| **无证据** | 三个 N 上区间上限都 ≥ 0 | 学习策略没有从紧迫信息中得到可检出的改善。看 M+Y：若它显著优于 M，提出的方法改为"学习的本地策略加 NR 式让路规则"；否则重新讨论核心表述中的摘要本身 |

- 三个 N 都要显著（交并检验），不需要多重比较校正，但比合并统计量更严格。
- 若某个 N 上 P2 显著变差（区间下限 > 0），无论其他 N 如何，都在报告中单列讨论。

### 5.3 次要判据与描述（预先写定解释，不改变主判据）

1. **用法：学习的响应对手写规则**。E_N = P2(U) − P2(M+Y)。
   - 若 E_N 在三个 N 中至少两个上显著 < 0，说明学习的响应优于手写规则；
   - 否则报告"手写规则已经得到大部分增益"，论文中把规则版本放在同等位置。
   - **进入最终确认的提出方法**：在 U 与 M+Y 中，取三个 N 上 P2 平均较低者。这是开发阶段的选择，最终由确认集检验。
2. **内容（H-S2）**：U − O、U − L 的配对差值，按 §3.4 的不对称方式解释。
   - U 显著优于 O：紧迫这一内容有价值，不只是"看得见"；
   - O 与 U 相当：摘要的内容改为"检测到的占用"，框架 §4.4 的 H-S2 按否定写。
3. **机制（H-M1、H-M2）**：
   - H-M2：P2(U∅) − P2(U) 的区间下限 > 0；
   - H-M1：P2(U−N) − P2(U) 的区间下限 > 0，且 U−N 失去的增益不少于 U − M 的一半；同时报告 U−U，看紧急 UE 自己是否也在利用广播。
4. **接收条件（H-B1）**：M+Y 与 U 的门限边界，以及 U₀ − U 在 0 dB 下的差值（§3.5）。
   - 解释预先写定：若 U₀ 在 0 dB 下仍不显著优于 M，"0 dB 下摘要信息不够"得到支持；若 U₀ 显著优于 M 而 U 在 0 dB 下不显著，说明 U 的损失来自训练与评估条件不一致。
5. **负载（H-B2）**：N = 6–16 上的 D_N 与区间，标出增益显著的负载范围。N = 6 与 16 不进入主判据。
6. **信息开销前沿上的点**：每个 N 上 M、U、CG-opt、N_EDF 的 P2，与每时隙比特数一起列表；XR-SBPC 的点由 EXP-012 补上。
7. **机制诊断**（描述性，定义同探针，以便对照）：
   - 不紧急的 UE 对被标记子信道的选择率，相对同一 RSSI 档未被标记子信道的倍数；以及被标记时的推迟率；
   - 失败 UE 的同信道碰撞类型：进入、被进入方新来、共处、同时新进；
   - 被推迟的 UE 自己的可靠性：按 UE 统计推迟次数，与其违约率对照；
   - 按 UE 平均信噪比与业务类别分组的失败比例；
   - M 与 L0 方法的诊断用"影子"广播计算：AP 按 R1 照常计算 b，但不提供给策略。

## 6. 风险与局限

- **接收模型是假设**：θ_f = −10 dB 来自粗略的处理增益估算，没有链路级仿真支持；不计虚警。§3.5 的接收条件测试给出增益对门限的依赖，但网格上的结论同样以这一模型的形式为前提。
- **U 在其他门限下的结果是稳健性，不是上限**：U 只在 −10 dB 下训练；U₀ 只补了 0 dB 一点。−15、−5 dB 两点上没有对应训练的策略。
- **紧迫门限与让路规则来自探针**：门限 3 沿用第 0 步；"推迟而不换信道"是在探针切片的 4 个实例上看过冒烟结果后定的。本实验不再调整，评估在新的切片上进行。
- **"瓶颈在看不到别人的紧迫性"只能得到支持，不能得到证明**：U 优于 M 说明这一流程下多一项信息有用，不说明不存在只用本地信息、同样好的策略。
- **L 的结论不对称**（§3.4）。
- **重新选 M**（§4.1）会改变 M 的检查点。本实验报告两种选法下的 M，说明差别。
- **训练预算**：新增两项输入，网络结构与预算不变；若学习曲线未收敛，按 §3.2 如实报告。
- **自身歧义**：OR 汇总的广播里，紧急 UE 看不出标记是不是自己的；学习方法自己处理，规则沿用探针的处理。
