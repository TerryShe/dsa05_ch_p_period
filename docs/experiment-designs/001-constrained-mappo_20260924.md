# EXP-DSA05-001：逐 UE 约束下的 MAPPO 首轮实验

状态：**已定稿**。2026-09-24 用户确认 §7 的四项决定，进入第 0 阶段（实现与验收）。按 [MARL 实验协议 v1](../research/marl-protocol-v1.md) 执行。

§1 的基线数字已替换为正式校准结果。正式校准把 paced_sticky 的 margin 网格扩到 32；草案校准中 N=12 的最好可行基线是 random_max（8.74），扩大网格后为 paced_sticky margin=8（5.50）。

## 1. 研究问题

[基线校准报告](../results/baseline-calibration_20260924/report.md)（验证集，协议流程，正式运行）显示，负载越高，本地规则离最优越远：

| N | 满足约束的最好本地基线 | 能耗/上界 |
|---|---|---|
| 4 | paced_sticky（margin=0） | 1.00，已是最优 |
| 6 | paced_sticky（margin=0.25） | 1.78 |
| 8 | paced_sticky（margin=0.5） | 2.87 |
| 12 | paced_sticky（margin=8） | 5.50 |

本实验回答两个问题：

- **Q1**：在 N=8 与 N=12 上，分布式 MARL 能否在满足"每 UE 违约率 ≤ 5%"的同时，把能耗显著降到最好的可行本地基线以下？
- **Q2**：约束的处理方式有多重要？比较固定惩罚、全局拉格朗日乘子和逐 UE 局部对偶变量三种做法。

不在本轮范围内：N=4（本地规则已经最优，只作为训练框架的正确性检查）、衰落信道、网络结构消融。

## 2. 方法

三个变体共用同一套网络和训练框架，只在约束处理上不同。

### 2.1 公共部分

- **MAPPO**：所有 UE 共享一个 Actor（UE 匿名），另有一个集中式 Critic（只在训练时使用）。
- **Actor**：沿用 dsa04 中表现最好的 CSG 结构，即逐子信道共享的 GRU 加 DeepSets 融合，适配为 21 类动作（OFF，或 4 个子信道 × 5 个功率档）。输入全部来自本 UE 的 `UEObservation`，或可由它推出的量：
  - 每个子信道：上一时隙的 RSSI（dB，缩放）、本 UE 是否在该子信道发送及所用功率档、由 RSSI 推出的干扰估计（与 `baselines.estimate_link` 相同）；
  - 本 UE 自身：剩余比特/包长、距截止期时隙数/周期、周期/40、上一时隙的反馈、上一次的互信息/包长、自身增益估计（dB，记住最近一次的估计），以及变体 C 的对偶变量 μ_i。
  - GRU 记忆只在回合开始时清零，包与包之间保留，使 UE 能记住自己的增益和子信道占用情况。
- **Critic**：输入为全局状态，包括所有 UE 的局部特征、真实增益（dB）和各自的 μ_i。
- **奖励**（团队共享，每个时隙）：r_t = −Σ_i E_i(t)/E₀ − Σ_i μ_i(t)·c_i(t)。其中 E₀ = τ·p_max，是一个满功率时隙的能耗；c_i(t)=1 表示 UE i 在本时隙边界结算出一次违约。
- **折扣**：连续任务，γ=0.99（有效视野约 100 时隙，大于最长周期 40）；GAE λ=0.95；训练回合被截断时，用状态价值作 bootstrap。

### 2.2 三个变体

| 变体 | μ_i 的来源 | 执行时需要的信息 |
|---|---|---|
| **A 固定惩罚** | 常数 w。w 在验证集上从 {1, 3, 10, 30} 中按协议选模规则选定 | 无额外信息 |
| **B 全局拉格朗日** | 所有 UE 共用一个 μ，每轮 PPO 迭代之间按训练批次的平均违约率做对偶上升：μ ← [μ + η(v̄ − ε)]₊ | 训练结束后 μ 固定，作为常数使用 |
| **C 逐 UE 局部对偶（建议作为主线）** | 每个 UE 在回合内自己维护 μ_i：每到一个截止期就更新 μ_i ← clip(μ_i + η(c_i − ε), 0, μ_max)；μ_i 同时进入 Actor 输入和奖励 | 只用本 UE 自己的违约记录，执行时完全分布式 |

变体 C 的依据是状态增广约束强化学习（Calvo-Fullana, Paternain, Chamon, Ribeiro，arXiv:2102.11941）：把对偶变量作为状态的一部分，在执行期间在线更新，策略学会针对不同的 μ 作出反应。

它恰好适合本场景的难点：约束是逐 UE 的，但 UE 匿名，而且每个回合换一个新拓扑，所以不存在一个可以跨回合固定的"UE i 的乘子"。变体 C 让每个 UE 根据自身的违约情况就地调整：违约越多，μ_i 越大，策略就越倾向于用高功率、避开拥挤的子信道。训练时 μ_i 的初值在 [0, μ_max] 中随机抽取，以覆盖不同的状态；评估时固定一个初值 μ₀，在验证集上选定。

这是本项目有希望形成算法贡献的部分，但需要先做文献检索，确认与已有工作（包括通信领域的约束 MARL）的区别。

## 3. 训练

- **实例**：每个训练回合从训练池抽一个实例（`splits.sample_train_index`）。
- **回合**：从时隙 0 开始，长 600 个时隙（15 个最长周期），截断时 bootstrap。
- **并行与更新**：16 个并行环境，每次采样 128 个时隙；每轮 4 个 PPO epoch；学习率 Actor 3e-4、Critic 1e-3；熵系数 0.01，在前一半预算内线性降到 0。
- **预算**：
  - 短训：每个种子 200 万时隙，用来确认能学到东西、比较三个变体；
  - 长训：每个种子 2000 万时隙，只在短训显示出学习效果之后进行。
- **种子**：101、202、303。
- **验证与选模**：每 25 万时隙在验证集上评估一次（64 个实例 × 1 次执行），保存检查点，按协议规则选模。选中的检查点和最后的检查点都进入测试。
- **超参数**：变体 A 的 w、变体 B 的 η、变体 C 的 η、μ_max、μ₀，只能在验证集上调，调参次数计入报告。

## 4. 评估与预先登记的判读

按协议 v1：测试集 200 个实例 × 2 次执行 × 3 个种子。主表对每个 N 列出下界、上界、四个基线（其中 paced_sticky 使用校准后的 margin），以及 A、B、C 的选中检查点和最后检查点。

- **C1 可行**：F_test ≥ 0.95。
- **C2 节能**：在满足约束的方法中，与最好的可行基线做逐实例成对比较，能耗/上界之差的 95% 区间上限 < 0，才称"显著节能"。同时报告离上界和下界各有多远。
- **C3 约束方式**：C 分别与 A、B 做成对比较，看可行率和能耗/上界。
- **诊断**：功率档的使用分布（警惕 dsa04 中出现过的"学成始终最高档"）、子信道冲突率、每 UE 违约率分布、按距离的能耗，以及 μ_i 在回合内的变化轨迹。

## 5. 阶段

0. **实现与验收**：实现 Actor 特征、奖励与代价的记账、μ 的更新、训练与验证循环。测试需覆盖：违约代价只在截止期记一次；μ 的更新只使用本 UE 的信息；Actor 输入中没有真实增益和 UE 编号；把训练吞吐量实测出来。
1. **N=8 短训**：A、B、C 各 3 个种子（9 次训练，每次 200 万时隙）。
2. **长训**：若第 1 阶段中至少一个变体在验证集上满足约束，且能耗/上界低于校准后的 paced_sticky，就在 N=8 和 N=12 上对入选的变体做长训；否则先诊断，另立新的设计。

## 6. 风险

- 约束振荡：μ 的步长太大，会让策略在"违约"和"浪费能耗"之间来回摆动。
- 学成"始终最高功率"：这样一定可行，但不节能，dsa04 中出现过类似的吸引子。需要监控功率档分布。
- 团队奖励下的信用分配：N=12 时，每个 UE 对团队回报的影响很小。
- 实际吞吐量可能低于估计，从而拉长训练时间。实测后再调整预算。

## 7. 已确认的决定（2026-09-24）

1. 以变体 C（逐 UE 局部对偶）作为论文主线，A、B 作为对照；变体 C 的新颖性在写作前另做文献检索确认。
2. 预算分两档：短训 200 万、长训 2000 万时隙/种子。
3. Actor 沿用 CSG 结构。
4. 先在 N=8 上做短训，再扩展到 N=12。
