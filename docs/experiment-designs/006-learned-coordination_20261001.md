# EXP-DSA05-006：可靠性约束下的学习型分布式协调

状态：**已定稿**（第 1 版）。2026-10-01 用户确认 §11 的全部决定（无 CSI 消融与 XR-SBPC 式 SAC 都推迟），进入第 0 阶段（实现与验收）。

## 1. 研究问题与假设

场景 v2.0 的验证集校准（[报告](../results/v2-calibration_20261001/report.md)）给出了两个参照：

| 参照 | ε = 0.01 时的 N\* | 说明 |
|---|---|---|
| 集中式因果调度 N_EDF | 20 | AP 知道所有 UE 的队列与当前信道，有调度信令 |
| 最好的本地规则（校准后） | 4 | p 坚持、机会式、paced_sticky_csi 都达到 4；N = 6 时最好为 0.94 |

两者的失败方式不同：
- 本地规则在信道只占用 25–48% 时就失败，失败的通常是单个远端、快类 UE，违约率约 2%；
- EDF 只在信道占用率接近 0.9 的过载时失败。

所以本地规则与 EDF 之间的差距来自协调，而不是资源。

**问题**：只用本地信息（与本地规则相同的信息边界，场景规范 §4）、但通过集中训练学到的分布式策略，能把承载能力从 4 提高多少？它学到的协调方式是什么？

**预先写定的假设**（在测试集上判读，§6）：
- **H1**：学习型策略在 ε = 0.01 下的 N\* 高于最好的校准本地规则的 N\*。
- **H2**：在 N ∈ {6, 8, 10, 12} 上，学习型策略的 F_{0.01}(N) 高于该 N 上最好的校准本地规则，配对差的 95% 区间不含 0。
- **描述性**：报告缩小的差距比例 (N\*_MARL − N\*_local) / (N_EDF − N\*_local)，以及 ε = 0.05 下的同样结果。

如果学习型策略也停在 4 附近，这是一个有意义的负结果：在不交换信息的条件下，集中训练不足以学到所需的协调。届时下一步是研究最少需要多少信令（例如 AP 广播的子信道负载），另立实验。

## 2. 参照与基线（全部已冻结，不再调参）

- **N_EDF**（规范版，按松弛量排序），以及诊断用的 defer_hopeless 版；
- **本地规则**：random_max、sticky_max、p 坚持、机会式、周期预约、paced_sticky_csi，每类按 [`calibration.json`](../results/v2-calibration_20261001/calibration.json) 在每个 N 上使用冻结的参数；
- **"每个 N 最好的本地规则"**：每个 N 上，验证集 F_{0.01} 最高的那一类规则及其参数（平局按协议 v2 §5 的顺序），在测试前冻结。H1、H2 都与它比较。

XR-SBPC 式 SAC 在 v2.0 上的重做推迟（§11 第 7 项）：先看 MAPPO 能否超过本地规则，再决定在哪些 N 上训练。

## 3. 方法

主方法沿用 EXP-DSA05-001 的约束循环 MAPPO（CSG 演员加集中式评论家，[设计](001-constrained-mappo_20260924.md)），按场景 v2.0 做以下改动。

### 3.1 演员的输入（只用本地信息）

演员仍是逐 UE、逐子信道共享权重的 GRU，与 N 无关。特征改动：
- **自身当前增益**：每个子信道 token 增加一项，UE 本时隙在该子信道上的增益（`own_gain_w`，dB 归一化）。
- **各功率档的覆盖比**：原来按"从自己的反馈估计的静态增益"计算，v2 改为按当前自身增益除以上一时隙干扰估计计算。衰落下静态估计已无意义。
- **上下文**：原来的"增益已知"标志与静态增益估计，改为自身最好子信道的当前增益；其余不变（剩余比特、距截止期、周期、上一时隙结果与服务量、逐 UE 对偶 μ_i 等）。
- v1.0 场景下特征逐位不变（测试守护），已有的 EXP-001…005 结果不受影响。

信息边界与本地规则相同：看不到其他 UE 的队列、增益、动作、身份与 N。

### 3.2 与 N 无关的集中式评论家

v1 的评论家把所有 UE 的特征拼成一个定长向量，只能用于固定的 N。v2 改为集合结构：
- 每个 UE 的向量：它的演员特征、它在各子信道上的真实当前增益、它的 μ_i；
- 共享的编码器 φ 处理每个 UE，对一个环境内的所有 UE 取均值与最大值；
- 再拼上 N / 32，经 MLP 输出状态价值。

评论家只在训练中使用，执行时不需要。

### 3.3 奖励：只含可靠性

不考虑能耗，奖励中没有能耗项，也没有"空口占用"之类的代理项。每个时隙的团队奖励为：

  r_t = −(1/N) Σ_i μ_i(t) c_i(t)

其中 c_i(t) = 1 当且仅当 UE i 的包在时隙 t 末违约。两个变体：
- **A（固定权重）**：μ_i ≡ w。这相当于最小化全网平均违约数，不区分 UE。PPO 按批次标准化优势，所以 w 的大小不影响演员的更新，A 没有需要调的参数（取 w = 1）。
- **C（逐 UE 对偶）**：每个 UE 在自己的每次截止期结算时更新 μ_i ← clip(μ_i + η (c_i − ε), 0, μ_max)，ε = 0.01，演员观测 μ_i / μ_max。违约多于 ε 的 UE 权重上升，避免牺牲少数 UE。在 EXP-001 中，同类的全局乘子（变体 B）曾长期放弃远端 UE。
- 执行时 C 的 UE 自己更新 μ_i，与训练相同。初始 μ0 固定为 5（EXP-001 的默认值），不再像 v1 那样在验证集上选 μ0，以控制验证成本。

承载能力要求所有 UE 都满足 ε，所以预期 C 更合适。A 作为对照，用来检验逐 UE 处理是否必要。

**违约稀少**：ε = 0.01 时学习信号稀疏。本设计不预先加入塑形，第 1 阶段先看不加塑形能否学到（§4.1 的判据）；不能时，另行提出基于势函数的塑形，经用户确认后再加入。

### 3.4 一个策略覆盖多个 N

- 训练用 14 个并行环境，每个环境固定一个 N：{4, 6, 8, 10, 12, 16, 20} 各 2 个。
- 每个环境的每个回合都从训练池抽取新实例与新衰落（`splits_v2.training_fading_seeds`）。
- 所有环境的 UE 拼成一批送入演员（共 152 个 UE），不需要填充；评论家按环境分段汇聚。
- 训练用的 N 覆盖本地规则失败（≥ 6）到 EDF 失败（> 20）之间的区间。N = 2 太容易，N ≥ 24 时 EDF 也失败，都不放入训练；评估仍用完整网格。

### 3.5 训练设置

沿用 EXP-001 长训的设置：
- 回合 600 个时隙后截断（自举），rollout 128 个时隙；
- PPO：演员学习率 3e-4、评论家 1e-3，γ = 0.99，λ = 0.95，裁剪 0.2，4 个 epoch，熵系数 0.01 在前一半预算内线性衰减到 0；
- 隐层：演员 64，评论家 256。

预算按所有环境实际执行的时隙数计。

## 4. 实验

### 4.1 第 1 阶段：A 与 C 的筛选

- A 与 C，各 2 个种子，各 500 万时隙；
- 每 100 万时隙存一个检查点，训练后在验证集上并行评估（§5）。
- **选择**：两个变体各取其种子在最好检查点上的选模得分（§5）的均值，取高者。两者之差小于 0.02 时选 C（它逐 UE 保护可靠性，与承载能力的定义一致）。
- **学习信号判据**：若两个变体的最好得分都不高于最好的校准本地规则在同一得分上的值，说明不加塑形学不到有用的协调。届时暂停，向用户提出塑形方案，不进入第 2 阶段。

### 4.2 第 2 阶段：长训

- 选中的变体，3 个种子（101、202、303），预算 2,000 万时隙（第 0 阶段实测吞吐后确认，§10）；
- 每 200 万时隙存一个检查点，训练后在验证集上并行评估，按 §5 选检查点。

### 4.3 消融（推迟，用户决定 2026-10-01）

- **无自身 CSI**：演员不使用 `own_gain_w`，覆盖比改回按反馈估计。3 个种子，同预算。它回答"当前 CSI 对学习型协调的价值"（场景规范 §4 已登记为对照）。

## 5. 选模（验证集）

- **得分**：S = 验证集上 N ∈ {4, 6, 8, 10, 12, 16} 的 F_{0.01}(N) 的平均。
  - 这些 N 覆盖本地规则与 EDF 之间的区间；
  - 用平均而不是 N\*，因为 N\* 是离散的，64 个实例上波动大。
- 每个检查点在验证集 64 个实例 × 6 个 N 上评估（384 个 20,000 时隙的回合），用多进程在训练后进行。
- 每个种子选 S 最高的检查点，相同时选较晚的。同时报告最后一个检查点。
- 选中检查点再在验证集的完整网格上评估一次，只用于报告，不再参与选择。

## 6. 测试与预先写定的判读

方法冻结后，一次正式运行（`--formal --confirm-test`，干净的已提交工作树）：
- 学习型策略：选中的变体，3 个种子，选中与最后检查点；
- 全部校准本地规则（按 `calibration.json` 的逐 N 参数）、N_EDF 两版；
- 协议 v2 测试集 200 个实例，每个实例 1 次执行，完整网格（N_EDF 另算 36、40）。

判读：
- **F(N) 与 N\***：学习型策略的 F 先在每个实例上对 3 个种子取平均，置信区间用两层 bootstrap（种子 × 实例），N\* 按场景规范 §5.2。
- **H1**：N\*_{0.01}(MARL) > N\*_{0.01}(每个 N 最好的本地规则)，两者都在测试集上计算。同时报告 N\* 的 bootstrap 分布，以及"MARL 的 N\* 大于本地规则的 N\*"的 bootstrap 比例。
- **H2**：N ∈ {6, 8, 10, 12} 上，F_{0.01} 的配对差（MARL − 该 N 最好的本地规则）的 95% 区间下限 > 0。四个 N 分别判读，不做多重比较校正，但同时报告四个区间。
- **描述性**：缩小的差距比例；ε = 0.05 下的同样比较；A 与 C 的差别（若第 2 阶段只训练一个变体，则只报告第 1 阶段验证集上的差别）。
- 测试结果不再用于修改任何方法、超参数或选模规则（协议 v2 §6）。

## 7. 行为诊断（描述性）

回答"学到了什么样的协调"：
- 每 UE 违约率按类别、距离分组，与本地规则对照（远端快类 UE 是否得到保护）；
- 信道占用率、同一（时隙，子信道）上同时发送的 UE 数（碰撞）、子信道切换频率；
- 发送概率与自身增益、距截止期时隙数、上一时隙干扰的关系，以及近端 UE 是否在远端 UE 紧迫时让出子信道；
- 功率档的使用（不计能耗，只看功率是否被用来减少对他人的干扰）；
- C 变体中 μ_i 在 20,000 个时隙内的轨迹。

## 8. 风险与局限

- **违约稀少，学习信号弱**：§4.1 的判据用来尽早发现。
- **一个策略覆盖多个 N**：小 N 与大 N 的最优行为可能不同。演员看不到 N，只能从干扰推断负载。若第 1 阶段中某些 N 明显差于单独训练的预期，记为局限，必要时另立按 N 训练的对照。
- **训练 N 的分布**是人为选择，会影响各 N 上的表现。评估用完整网格，网格外推（N = 2、≥ 24）只作描述。
- **验证选模的噪声**：64 个实例上 F 的标准误约 0.03；S 对 6 个 N 平均，降低了噪声，但检查点之间的小差别不可信。
- **回合长度不一致**：训练回合 600 个时隙，评估 20,000 个时隙；C 的 μ_i 在长时域上的漂移只能在评估中看到。
- **计算成本**：v2 每个时隙的 UE 数是 v1 N = 8 时的 1.2 倍（152 对 128），并多了衰落。2,000 万时隙的耗时需在第 0 阶段实测（§10）。

## 9. 第 0 阶段：工程与验收

**代码**（v1.0 与 EXP-001…005 的行为逐位不变）：
- `marl/features.py`：v2 的 token 与上下文（§3.1），由 `UEObservation.own_gain_w` 是否存在决定；
- `marl/networks.py`：集合评论家（§3.2）；
- `marl/trainer.py`（或新的 `trainer_v2.py`）：固定 N 的多环境、拼接 UE 批次、分段汇聚、只含可靠性的奖励、按 `splits_v2` 抽取训练实例与衰落、只存检查点不做训练中的验证；
- `experiments/train_capacity_mappo.py` 与配置 `configs/exp006-*.toml`；
- 检查点的验证与测试评估：`evaluate_capacity` 支持 MARL 检查点与"按 N 校准的本地规则"两种新策略规格，多进程运行；
- 选模脚本：按 §5 计算 S 并选检查点。

**测试**：
- v1 特征与评论家输入逐位不变；
- v2 token 中的自身增益等于观测中的 `own_gain_w`，覆盖比按当前增益计算；
- 集合评论家对 UE 的排列不变，对不同 N 的输入都能运行；
- 拼接批次的演员输出与逐环境分别计算的结果一致；
- 奖励只含违约项，与环境的结算一致（复用 v1 的结算一致性断言）；
- 训练从训练池抽取实例，验证与测试代码拒绝训练池以外的混用；
- 按 N 校准的本地规则在每个 N 上恰好使用 `calibration.json` 中的规格。

**吞吐实测**：一个 A 的种子跑 20 万时隙，记录每秒时隙数与内存，据此确认 §10 的预算。若 2,000 万时隙单个运行超过 24 小时，向用户提出降低预算或减少环境数。

## 11. 已确认的决定（2026-10-01）

1. **主方法**：约束循环 MAPPO（CSG 演员加集合评论家），一个策略覆盖多个 N。
2. **奖励**：只含可靠性；变体 A（固定权重，w = 1）与 C（逐 UE 对偶，ε = 0.01，μ0 = 5）。不加能耗或空口占用项；塑形只在 §4.1 的判据触发后另行提出。
3. **训练的 N**：14 个环境，{4, 6, 8, 10, 12, 16, 20} 各 2 个。
4. **选模**：S = N ∈ {4, 6, 8, 10, 12, 16} 的验证集 F_{0.01} 平均；检查点在训练后并行验证。
5. **预算**：第 1 阶段 2 × 2 × 500 万；第 2 阶段 3 个种子 × 2,000 万（第 0 阶段实测后确认）。
6. **无 CSI 消融**：推迟，不在本实验内。
7. **XR-SBPC 式 SAC**：推迟。先看 MAPPO 能否超过本地规则，再决定在哪些 N 上训练。
8. **判读**：H1、H2 如 §6 所写，只在测试集上判读一次。

## 12. 第 0 阶段验收（2026-10-01）

**实现**（§9 的全部条目）：
- `marl/features.py`：观测带 `own_gain_w` 时，token 末尾加自身当前增益，覆盖比按当前增益计算，上下文的增益位置为"已知"与最好子信道的当前增益；`critic_ue_features`、`critic_ue_dim`。
- `marl/networks.py`：`SetCritic`（逐 UE 编码，按环境取均值与最大值，加 N / 32）。
- `marl/trainer_v2.py`：
  - `CapacityTrainer`：固定 N 的多环境，拼接 UE 批次，只含违约项的奖励，按 `splits_v2` 抽取训练实例与衰落，只存检查点；
  - `RaggedMAPPO`：按环境分段的 PPO 更新；
  - `load_capacity_policy`：任意 N 的执行策略。
- `experiments/train_capacity_mappo.py`；配置 `configs/exp006-capacity-mappo.toml`（第 1 阶段）、`configs/exp006-capacity-mappo-long.toml`（第 2 阶段）。
- `rules_v2.make_policy_v2` 新增三种策略规格：
  - `marl:<检查点>`；
  - `calibrated:<规则类>`（按 `calibration.json` 的逐 N 参数）；
  - `best_local`（每个 N 最好的校准本地规则，§2）。
- `experiments/select_capacity_checkpoints.py`：§5 的得分 S、逐运行选检查点、§4.1 的变体选择与学习信号判据。

**测试**（`tests/test_marl_v2.py`，全部测试 197 个通过）：
- v2 token 中的自身增益与覆盖比；
- 集合评论家的排列不变性与任意 N；
- 拼接批次与逐环境计算一致；
- 拼接 rollout 的形状、奖励非正、PPO 回放的对数概率误差 < 1e-5、训练实例全部来自训练池；
- 检查点策略能在训练时没有的 N（= 5）上运行；
- 校准规格与 `best_local` 和 `calibration.json` 一致；
