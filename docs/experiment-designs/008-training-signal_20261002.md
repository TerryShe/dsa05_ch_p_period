# EXP-DSA05-008：固定 OBS 下的训练信号、更新方式与逐 UE 可靠性反馈

状态：**已定稿（2026-10-03，用户批准；第 3 版）**。第 3 版加入固定开发筛选集、筛选集逐 N 保护、R0 复现检查、学习曲线报告、ValueNorm 更新时机说明与优势方差分解诊断。

- 下一步是第 0 阶段（§9）：工程与验收，以及筛选集与确认集的机器清单。
- 定稿时已核查：v2 的开发实例只用过 0–63（第 0 阶段量级检查）与 1,000–1,399（第 0 步失败分解），没有 v2 运行读取过 2,000–2,255 或备用池实例。
- 第 0 阶段的实现提交并通过验收之前，不训练，不读取筛选集 2,000–2,255 或确认集。

## 1. 客观分析与研究问题

### 1.1 已有证据及其边界

EXP-006 变体 A 在中等负载上优于本地规则，但 ε = 0.01 下测试集容量点估计仍为 N\* = 6，与 `best_local` 相同。验证集上两者为 4，且学习方法的 F(6) = 0.948、F(8) = 0.938，说明 N = 6、8 都应进入门槛筛选，不能仅针对旧测试集的 N = 8 调参。后续设计已利用旧测试结果，正式判读必须使用新确认集。

[第 0 步报告](../results/step0-failures_20261002/report.md) 提供两类线索：

1. **干扰相关的改善空间**：EXP-006 三个学习型模型的失败 UE 错过的包中，52–82% 在保持自身实际发送、去掉其他发送方后能送达（`best_local` 为 59–86%）；干扰方的无干扰瞬时松弛量有 98–100% ≥ 3。去掉这些干扰类违约后，学习型模型 67–88% 的失败 UE 可满足额度。这是逐包反事实上限，不是可实现的联合调度；它没有计入让路者随后违约、衰落变化及局部信息下的可辨识性。因而只能提出“能否学到更好的协调”，不能写成“已证明这些干扰可安全消除”。
2. **跨 N 的训练差异**：原配置有 152 个 UE，N = 16、20 占潜在 UE 时隙样本的 47.4%；训练奖励的绝对量级也远大于 N = 6、8。实际演员损失只计有包样本，真实占比须另行测量。奖励均值、样本数和统一优势标准化不足以直接证明梯度被大 N 淹没；还需检查优势、价值误差、梯度方向及裁剪。

失败包窗口内几乎始终发送，也不等于失败 UE 的信道选择或功率策略已最优。干扰与训练差异值得检验，但目前都没有确立唯一的因果解释。

### 1.2 本实验回答什么

在执行 OBS 的信息来源、字段和维度不变的条件下，检验：

- 优势标准化、演员权重、价值归一化、训练负载分布及 PPO 更新方式，能否改善门槛区可行率；
- 在筛选后的训练设置上，现有逐 UE 对偶反馈 C 与较长回合能否进一步改善结果；
- 相同训练预算、相同选模规则下，是否提高 ε = 0.01 的容量点估计。

**范围保留**：不新增 OBS 或信令，不做逐 UE 信用分配、反事实奖励或表示学习辅助任务。新增 F5 仍属于训练更新方式，符合这个范围。

### 1.3 对论文主线的意义

EXP-008 是建立可靠基线、排查训练瓶颈的实验，单靠 ValueNorm、mini-batch 或采样调参，通常不足以形成目标期刊的主要算法贡献。即使成功，也需证明机制、稳定性与场景适用范围。

A 的每时隙平均违约奖励与最终“每个 UE 满足包违约率、95% 部署可行”的目标并不等价：其长期期望仍按包到达频率加权。C 也是现有对偶反馈的代理方案，本实验没有直接实现最差 UE 或部署尾部风险目标。失败不证明固定 OBS 无法协调，也不证明信用分配一定是下一步唯一答案；后续可分别研究目标、信用分配或记忆。

## 2. 对照与不变的部分

- **执行信息边界**：演员输入字段、维度、动作集和网络结构与 EXP-006 相同。C 的 μ_i 使用已有上下文位置，由自身包结算历史计算；没有来自其他 UE 的新增信息。A/C 的该位置取值与本地更新行为不同，不能描述成两者接收完全相同的数值输入。
- **场景与评估**：场景 v2.0、协议 v2 的冻结核心、训练池、评估时域与可行判据保持不变。
- **训练**：演员与评论家结构、rollout 长度 128、学习率、γ = 0.99、λ = 0.95、裁剪、4 个 epoch、熵衰减、梯度裁剪保持原设置；仅改变表中对应因素及第 2 轮列明的变量。
- **奖励**：第 1 轮保持 A 的 `-(1/N) Σ_i c_i`，不加入奖励塑形。第 2 轮 C 使用原有逐 UE 权重，不另行改变奖励公式。
- **预算**：按环境时隙之和计算，保持原训练器的 rollout 边界取整方式，报告实际时隙；不是 UE 时隙数，也不是优化器步数。
- **R0**：`configs/exp006-capacity-mappo.toml` 的 A，在同一实现提交上重新运行第 1 轮。默认路径须通过与原实现的一致性验收。R0 的解析设置、种子与 EXP-006 第 1 阶段的 A（`outputs/exp006-phase1/fixed-seed101`、`fixed-seed202`，提交 2e0c691）完全相同，因此同时作为整段训练的复现检查（§4.4）。

## 3. 第 1 轮：五个单因素

每个因素只改变一项机制，其余与 R0 相同。原负载分布为 {4, 4, 6, 6, 8, 8, 10, 10, 12, 12, 16, 16, 20, 20}。

| 代号 | 因素 | 具体做法 | 可检验的解释 |
|---|---|---|---|
| R0 | 对照 | EXP-006 变体 A | 原训练设置 |
| F1 | 按 N 标准化优势 | 每个 rollout 内，按 N 汇集有包 UE 的优势，分别中心化并除以组标准差；分母下限 1e-8 | 跨 N 的优势尺度与相对训练权重是否影响门槛区 |
| F2 | 按环境等权的演员损失 | 每个 mini-batch 内，先对每个环境的有包 UE 时隙平均，再对有有效样本的环境平均；熵项使用同样权重 | UE 数量和有效样本数造成的环境权重差异是否重要 |
| F3 | 全局 ValueNorm | 全部环境的未复制 returns 共用一组运行均值、方差；评论家回归归一化目标，GAE 与 bootstrap 使用还原后的价值 | 标准 MAPPO 价值尺度稳定化是否有效 |
| F4 | 偏向门槛区的 N 分布 | 14 个环境改为 {4, 6, 6, 6, 8, 8, 8, 10, 10, 10, 12, 12, 16, 20} | 增加门槛附近训练覆盖是否有效 |
| F5 | 不切 mini-batch | `minibatch_envs = 14`，每个 epoch 对整个 rollout 做一次演员和评论家更新；epoch 数仍为 4 | 较大的梯度批次和较少的顺序更新是否改善训练 |

### 3.1 F1–F4 的修订与实现口径

- **F1 保留，但不是无影响的尺度处理**：按 N 改变尺度也会改变跨 N 的代理目标权重。没有有效样本的组跳过；零方差组的中心化优势为 0，不强行满足标准差为 1。组合 F4 后各 N 不再都有两个环境，分组逻辑须按实际配置处理。奖励为零仍可能存在价值残差，不能直接把“零违约 rollout”当作零梯度。
- **F2 保留**：熵项须同步改权重，避免另引入不同的正则化强度。mini-batch 内环境等权不保证整个 epoch 的实际更新贡献严格相等，因为当前尾批只有两个环境且仍做完整一步更新。保留该尾批以维持单因素对照，在 F5 中检验整体批次。
- **F3 从按 N ValueNorm 改为全局 ValueNorm**：先建立 MAPPO 原文建议的基线。按 N 分组归一化是额外扩展，会引入分组统计及不同尺度下的价值拟合权重，不应直接称为原文做法。本轮不同时加入这项扩展；价值误差仍按 N 诊断。
  - 统计量每个 rollout 仅更新一次，使用 `[时间, 环境]` 的 returns，不按 UE 复制、不随 mini-batch 或 epoch 重复更新。
  - 采样价值、下一状态价值和 GAE 先使用采样时统计量还原到奖励单位；之后更新统计量，冻结于本次全部 PPO epoch，归一化回归目标。
  - 运行统计参考[作者 ValueNorm 实现](https://github.com/marlbenchmark/on-policy/blob/main/onpolicy/utils/valuenorm.py)：β = 0.99999、去偏分母下限 1e-5、方差下限 1e-2。记录下限触发情况，不在观察效果后改下限。
  - **更新时机是对原实现的有意偏离**：原实现在 `r_mappo.py` 的 `cal_value_loss` 中对每个 mini-batch 调用 `value_normalizer.update`，每个 rollout 更新 epoch × mini-batch 次，同一 epoch 内各 mini-batch 的归一化目标也随之变化。本实验每个 rollout 只更新一次，原因有二：使 F3 与 F5 组合时统计量的更新频率不随 mini-batch 数改变；使一次更新的全部 epoch 回归同一组目标。因此 F3 只沿用原实现的数值参数，结果不能称为原文 ValueNorm 的复现。
  - **β 下统计量近似全程累计平均**：500 万时隙约 2,791 个 rollout，最早一次更新的相对权重 β^2791 ≈ 0.97；2,000 万时隙约 11,161 次，≈ 0.89。按原实现的时机（R0 的切分下每 rollout 16 次），500 万时隙后约为 0.64。训练中违约率下降时，统计量会滞后于当前 returns 的尺度。不在本轮改 β；按 §8 记录滞后程度。
  - 检查点保存统计量、去偏状态及归一化配置；不做 PopArt 式输出层重标定。
- **F4 保留**：潜在 N = 6、8 UE 样本占比由 18.4% 升到 30.9%，环境占比由 28.6% 升到 42.9%；总 UE 数由 152 降为 136。环境时隙预算相同，但 UE 样本量和计算量不同，须同时报告；不能声称所有样本与计算预算都相同。

### 3.2 为什么加入 F5

[MAPPO 正式版 §5.3](https://proceedings.neurips.cc/paper_files/paper/2022/file/9c1535a02f0ce079433344e14d910597-Paper-Datasets_and_Benchmarks.pdf) 比较每 epoch 的 1、2、4 个 mini-batch，建议多数情形不切分。这是游戏任务中的经验发现，不是无线场景的普适结论；因此加入单因素检验，而不直接替换 R0。

本项目的 `RaggedMAPPO.update` 按完整环境轨迹切分，14 个环境、`minibatch_envs = 4` 实际形成 **4 + 4 + 4 + 2**，不是四个等大批次。每个 rollout 有 1,792 个环境时隙、最多 19,456 个 UE 时隙样本。两种设置均使每个样本参与 4 个 epoch，但通常每个演员/评论家优化器的更新次数由 **16 次降为 4 次**；无有效演员样本时该演员更新跳过。

F5 保持学习率、epoch 数、rollout 和环境预算不变，不用学习率乘 4 或改成 16 个 epoch 来补步数。结果解释为“整体 PPO 更新方式”的效果，包含批次大小、顺序更新次数与尾批的差别，不能单独归因为梯度估计更准确。若将来需要分离机制，另行预登记更新次数匹配的消融，不在本轮临时增加。

不切批次提高峰值内存，吞吐未必按更新次数同比提高。第 0 阶段只在开发运行上测内存与吞吐，不修改科学筛选规则。

## 4. 第 1 轮预算、得分与组合验证

### 4.1 预算与选模

- R0、F1–F5，每条件种子 101、202，各 500 万环境时隙；每 100 万保存检查点。共 **12 个运行、60 个检查点**。
- **固定开发筛选集 exp008-screen256**：dev 实例 **2,000–2,255（半开区间 [2000, 2256)）**，256 个部署，仅 N ∈ {6, 8}，每部署一次执行，沿用 v2 的 dev 编码 0、衰落/执行派生和完整 20,200 时隙评估回合。所有条件、检查点及 A-near 使用同一组实例和公共随机数。
- **主得分 S_near** 在上述筛选集上计算：`[F_{0.01}(6) + F_{0.01}(8)] / 2`。每个检查点 **512 个回合**。每个种子按 `(S_near, 检查点时隙)` 从大到小选择，相同时取较晚者，再对两个种子的选中得分取平均；R0 使用相同规则。
- **旧验证集继续提供副指标和退化保护**：每个运行的筛选集选中检查点，评估原 64 实例 × N ∈ {4, 6, 8, 10, 12, 16}，计算 S_thr（{6, 8, 10, 12}）与 S_006（{4, 6, 8, 10, 12, 16}）；另评估验证 N = 2。每个运行合计 **448 个验证回合**。
- 不再为每个检查点都计算旧验证集副得分，也不以 S_thr 为检查点平局条件。检查点先由筛选集唯一确定，随后才检查验证保护；保护失败时不在该运行内换下一个检查点反复尝试。B1 的已选候选间仍可按 §4.3 的预定 S_thr 规则决胜。
- 筛选集与旧验证集都参与开发选择，均不用于正式显著性结论；新的确认集继续独立保留。

改主得分的原因：若只改善 F(8) 0.02，原 S_thr 只增加 0.005，达不到原来的 0.02 保留门槛，尽管这可能已经跨过容量门槛。另一方面 N = 6 也是验证集瓶颈，故不只选 F(8)。S_near 增加 0.01 对应一个门槛点增加 0.02、另一点不变。

**采用新筛选集的依据**：原 64 实例已用于 EXP-006 选模与规则校准，且分辨率不足。两个种子、两个 N 的均值得分，净增加三个可行标记即可越过 0.01 门槛。换为 256 实例后，需要至少净增加 11 个标记。

| 数量 | 原 64 实例 | 新 256 实例 |
|---|---|---|
| 单个种子、单个 N 的 F 步长 | 1/64 = 0.015625 | 1/256 = 0.00390625 |
| 两种子合并 S_near 的最小步长 | 1/256 = 0.00390625 | 1/1024 = 0.0009765625 |
| ΔS_near ≥ 0.01 的最少净增加可行标记 | 3 | 11 |
| 单个固定策略、单 N、F = 0.95 的二项标准误（量级参考） | 约 0.0272 | 约 0.0136 |

可行标记按“部署 × N × 训练种子”计数，不是独立部署数：嵌套的 N 和共享部署的种子结果相关。得分步长缩小四倍，部署抽样标准误约减半，不能称为不确定性下降四倍。

重新核算 EXP-006 的 30 个长训检查点，原验证集 S_near 的相邻检查点绝对变化中位数，在三个种子中均约为 0.0234。变化包含真实策略变化，不能全部当作抽样噪声；扩充筛选部署也不能消除“取最好检查点”的选择偏差。0.01 仍是探索性效果阈值，不是显著性门槛，跨种子、末段保护与独立确认保留。

**使用记录与登记**：本次检查可见的 36 份 v2 汇总/manifest，并核对第 0 步开发范围 1000–1399，未发现与 2000–2255 重叠的运行记录。定稿时再次核查并建立独立筛选清单，冻结范围、N、重复数、评估时域、种子派生、实例/衰落摘要和选择规则；不修改冻结的 dev 池边界。筛选实例不进入训练池，不根据其难例重新采样训练，也不在观察结果后替换或扩充实例。

### 4.2 保留规则

各差值均相对 R0，使用各自由新筛选集选中的检查点。一个因素同时满足以下条件才进入组合候选：

1. **新筛选集**上，两个种子的平均 **ΔS_near ≥ 0.01**，且两个种子各自的 ΔS_near 均 ≥ 0。
2. **旧验证集**上，平均 F(4)、F(6)、F(8) 和 S_thr 各自相对 R0 的下降均不超过 0.01。
3. **新筛选集**上，用固定的 400 万、500 万检查点计算两个种子合并的末段平均 S_near，差值 ≥ 0，避免仅凭一个瞬时峰值保留；不使用每个运行自行挑选的两个末段峰值。
4. **旧验证集**上，已选模型的平均 F(2) ≥ 0.95，且比 R0 的下降不超过 0.01；此检查不再重选检查点。
5. **新筛选集**上，已选模型两个种子的平均 F(6)、F(8) 各自相对 R0 的下降均不超过 0.01。这一条防止靠一个 N 的提高掩盖另一个 N 的下降，并与确认集 H2 中 N = 6 的非劣界一致。

这些阈值是事先规定的探索性筛选规则，不是显著性检验。256 个筛选部署提高部署层面的分辨率，但两个训练种子仍限制对训练随机性的判断；旧验证集的保护指标也仍然较粗。未保留只表示未通过当前预算与规则，不能写成该机制无效。

### 4.3 B1 不能由单因素结果直接推断

- 无因素保留：B1 = R0；一个因素保留：B1 = 该因素。
- 至少两个因素保留：增加 **COMB**，将全部保留因素组合，使用同样两个种子、500 万时隙、选模与验证流程；最多增加两个运行。
- 候选为 R0、保留的单因素与 COMB。组合若未通过 §4.2 的改善和退化保护，不参与 B1 选择；R0 始终是回退候选。
- 在合格候选的最高平均 S_near 以下 0.005 内，先取因素更少者，再取 S_thr 较高者，最后按 R0、F1…F5、COMB 的顺序决胜。选中的记为 B1。
- 保留全部单因素、组合结果及最后检查点结果，报告交互造成的退化。一次 COMB 不能识别所有两两交互，本轮不做完整因子实验。

### 4.4 R0 的整段复现检查

EXP-006 第 1 阶段的 A 与 R0 使用相同的解析设置与种子：
- 预算 5,001,472 时隙，`torch_threads = 1`，torch 2.14.0+cpu（当前环境相同）；
- 检查点在 1,001,728 … 5,001,472 时隙，每个运行 5 个；
- 检查点保存演员、评论家、两个优化器、mini-batch 洗牌生成器及全部随机数状态。

- **比较内容**：
  - 检查点的全部张量与随机数状态（不比较文件哈希，因为元数据可能不同）；
  - `training.jsonl` 的逐迭代指标。
- **时机**：R0 两个种子的 100 万检查点产生后立即比较。比较通过前，不评估任何条件的任何检查点；之后每个检查点产生时继续比较。
- **不一致时先定位原因**：在当前环境用提交 2e0c691 重跑同种子的前 20 次迭代，与原 `training.jsonl` 比较。
  - **旧提交能复现**：说明新实现改变了默认路径，按技术故障处理。停止第 1 轮全部运行，修复后以原条件重跑；修复前不查看任何筛选得分。
  - **旧提交也不能复现**：说明环境不再确定。记录首个分歧的迭代与指标差异量级，继续第 1 轮；R0 仍是同一提交上的对照。另把第 1 阶段 A 的 10 个检查点在筛选集上评估（5,120 个回合），描述性地报告两次同设置训练的 S_near 差异；保留规则仍只用新的 R0。

  - 检查点一致时，R0 已选模型在旧验证集上的 F(N) 应与第 1 阶段对应批次的结果完全相同（`docs/results/exp006-phase1_20261001/validation-batch-*.json`）；

### 5.1 C 的正确解释与参数

- 沿用 EXP-006：η = 2、ε = 0.01、μ_max = 50；训练回合初值仍逐 UE 均匀取自 [0, 50]，执行初值 μ0 = 5。表中的执行初值不意味着训练也从 5 开始。
- 原更新 `μ_i ← clip[μ_i + η(c_i − ε), 0, 50]` 是包结算时钟上的局部对偶反馈，不是精确的“累计额度使用量”；裁剪和重置会丢弃历史，μ_i 也没有显式表示剩余评估窗口。
- C 的 μ_i 与权重均属于现有 C 机制，无新 OBS，但与 A 的比较包含反馈、奖励尺度和输入数值分布的整体变化。它不构成对严格风险约束最优性的检验。
- 若 F3 在 A 的单因素筛选中未保留，第 2 轮也不临时只给 C 添加归一化。必须记录 C 的价值误差与 μ 分布；C 失败不能据此否定归一化后的 C 或逐 UE 约束方法。
- 训练初始化与执行初始化有分布差异；本轮固定以避免同时调参，并在结论中列明。

### 5.2 长回合能检验什么

600 时隙约有 60/30/15 个快/中/慢类包，2,400 时隙约有 240/120/60 个。较长回合改变隐藏状态、μ 和同一部署的持续时间，也减少同预算下的新部署数。

**2,400 仍没有对齐 20,000 时隙评估窗口**：按评估的整数额度口径，慢类 60 个包的 1% 额度仍为 0；训练 C 本身并不显式计算这个额度。rollout/BPTT 仍为 128，γ、λ 不变，GAE 权重的几何尺度约为 1/(1−γλ) = 16.8 时隙；不能将长回合写成已扩大长期信用分配范围。该比较主要检验状态持续性、启动效应与部署覆盖的折中。

### 5.3 B2 的选择

先排除相对 A-600 未通过 §4.2 第 2、4、5 项退化保护的条件；A-600 保留为基准候选。对其余条件取平均 S_near 最高者，最高值以下 0.005 内按 A-600、A-2400、C-600、C-2400 的顺序取较简单者，记为 B2。同样报告末段稳定性，不在观察结果后扩大回合长度或调整 μ 参数。

### 7.2 方法、网格与统计

完整网格 {2, 4, 6, 8, 10, 12, 16, 20, 24, 28, 32} 上评估：

- EXP-008 三个种子的选中与最后检查点，重复路径去重；**选中模型是唯一主方法**，最后模型只作稳定性报告。
- A-near 三个模型作为主算法对照；A-original 三个模型作为历史对照，重复路径去重。
- `best_local` 及协议要求的六类冻结校准本地规则，不能在确认集重新选择规则或参数。
- N_EDF 规范版与 `defer_hopeless` 版，另算 N = 36、40。

学习方法按三个训练种子的 F 取平均，再按协议的 **first-drop** 规则求 N\*；不是三个 N\* 的平均。N\* 使用未四舍五入的 F，首个 F < 0.95 之前的网格点为容量，包括 N = 2、4 的早期退化；不跳过低点，也不改用更后面的最大可行点。

统计沿用协议：10,000 次 bootstrap、种子 20260930。**方法间实例配对、各 N 联合重抽；两种学习方法的训练种子各自重抽**，与现有 `_bootstrap` 的口径一致。相同训练种子编号不意味着相同训练轨迹，不能将当前实现称为两层都严格配对。规则只有实例层。差值与 N\* 的联合分布须直接计算，不能用两条各自置信区间的重叠代替差值检验。

### 7.3 主判读

令 M 为 EXP-008 选中模型，B 为 A-near，L 为 `best_local`；以下全部只在 v2-confirm1 上判读：

- **H1（容量点估计）**：N\*_{0.01}(M) > N\*_{0.01}(B)。
- **H2（门槛改善及保护，联合条件）**：F_{0.01}(8; M) − F_{0.01}(8; B) 的双侧 95% bootstrap 区间下限 > 0；同时 F_{0.01}(6; M) − F_{0.01}(6; B) 的区间下限 > −0.01。后者是预先规定的部署可行率非劣保护界，与包违约率 ε 的含义不同。
- **H3（超越冻结本地规则的容量点估计）**：N\*_{0.01}(M) > N\*_{0.01}(L)。

原草案要求 N = 6、8 都显著优于 A，但旧测试 F(6) 已约 0.983，存在明显天花板；这会把没有显著增益的已可行点变成一票否决。现改为 N = 8 优越性加 N = 6 非劣保护，不要求天花板点也继续显著提高。两项作为同一个联合成功条件，不在不同 N 中挑选显著者。

**H1、H2、H3 同时满足**时，报告“新确认集上容量点估计提高，并有门槛可行率改善的统计支持”。H1/H3 自身不是容量差异显著性检验；F 的点估计 ≥ 0.95 也不等于总体可行率已被 95% 置信保证 ≥ 0.95。

| 结果 | 允许的解释 |
|---|---|
| H1、H3 成立，H2 不满足 | 跨过经验容量门槛，但门槛增益或非劣保护的统计证据不足 |
| H2 满足，H1 或 H3 不成立 | 门槛可行率得到支持，但尚未同时提高相对两类基线的容量 |
| 仅 S_thr 或中高 N 改善 | 训练设置改善部分负载性能，没有证明主容量目标达成 |
| C 被选中且确认成功 | 该具体训练设置下的本地对偶反馈方案有效，不能推论一般风险约束已解决 |
| 全部未满足 | 当前机制、预算、筛选规则下的负结果；不能证明固定 OBS 不可行或信用分配必需 |

描述性结果：A-original 对比、各种子/最后检查点、完整 F(N)、S_near/S_thr/S_006、ε = 0.05、失败构成、与 EDF 的差距，以及 N\* 和容量差的联合 bootstrap 分布。bootstrap 中容量领先的频率不当作后验概率或未经定义的 p 值。其他 N 上的单点区间均标为描述性，不追加新的正式成功条件。

## 8. 训练诊断与风险

- 每个 N：潜在和实际有包样本数、包结算数/违约率、零违约 rollout 占比、原始与标准化优势均值/标准差、returns 与原始单位价值误差、解释方差。目标方差为零时解释方差记为未定义。
- 梯度：固定诊断 rollout（定义见下文"优势的方差分解"）上，记录各 N 的损失梯度范数及与总梯度的方向关系；不同梯度会抵消，不把范数占比称为可加的真实“贡献比例”。诊断不改变训练更新。
- PPO：每 rollout 的实际优化器步数、样本量、KL、裁剪比例、梯度裁剪触发、有效批次大小；F5 尤其检查其收益是否伴随更小的累计策略变化。
- ValueNorm：运行统计、方差下限触发比例、归一化/原始单位的价值误差；统计更新时间不得受 mini-batch 数影响。另外每个 rollout 记录运行均值、标准差与该 rollout 自身 returns 的均值、标准差之比（全体与按 N），用来量化 §3.1 所说的统计滞后。
- **优势的方差分解**（描述性，不改变训练与筛选规则）：
  - 把 GAE 按 δ_t = r_t + γ(1 − d_{t+1}) V_{t+1} − V_t 拆成两部分，截断与终止掩码和训练时相同：
    - 奖励部分 Â^r_t = Σ_l (γλ)^l r_{t+l}；
    - 价值部分 Â^v_t = Σ_l (γλ)^l [γ(1 − d_{t+l+1}) V_{t+l+1} − V_{t+l}]；
    - 两者之和就是 Â_t。
  - 按 N 在有包 UE 样本上（与演员损失相同的样本）计算：Var(Â^r)、Var(Â^v)、2Cov(Â^r, Â^v) 各占 Var(Â) 的比例，以及非零奖励时隙数。一律用原始奖励单位、标准化之前的值。
  - **数据**：使用与梯度诊断相同的固定诊断 rollout，即从训练池按固定种子抽取的训练设置回合；所有条件统一使用 R0 的 N 分布，每个 N 合计 12,800 个环境时隙。不使用筛选集、开发诊断实例或确认集。
  - **检查点**：所有第 1 轮条件、两个种子的 100 万、300 万、500 万检查点。
  - **用途**：区分 §1.1 的两种情况。若 N = 6、8 上价值部分占绝大部分，说明门槛区的优势主要是价值残差，"信号本来就稀少"比"信号被大 N 淹没"更贴切，F1 主要会放大噪声。若奖励部分占比可观，而统一标准化后其尺度相对大 N 很小，则更支持"被淹没"的解释。只作描述，不作为保留规则或因果结论。
- C：按业务类别和回合位置记录 μ 分布、到达 0/50 的比例、训练与执行初始状态差异。
- 计算与覆盖：峰值内存、时隙吞吐、UE 样本吞吐、墙钟时间、抽到的不同部署数及类别覆盖。

小 N 的奖励稀疏，F1 可能主要放大价值噪声；5M 筛选也可能漏掉起步慢的设置。第 1、2 轮的多重选择和反复使用固定 256 实例筛选集、64 实例验证集仍会造成选择偏差；新筛选集最初未用于 EXP-006 选择，不意味着反复选择后依然是独立检验。正式证据只能来自冻结后的新确认集。两个筛选种子、三个长训种子限制对训练随机性的推断；增加筛选或确认部署无法补足训练种子不足。

不在观察结果后改变阈值、添加塑形或扩大因素表。技术故障须记录、使用原条件重跑；性能不佳不算技术故障。若确认结果不确定，不追加本确认集样本“直到显著”，后续比较另行登记新的确认集。

- 分析脚本：实现主方法/主基线分组、实例配对与跨 N 联合重抽的差值和容量分布，去重仅用于计算，不能改变方法的统计分组。
- R0 复现比较脚本：逐张量比较两个检查点的演员、评论家、优化器、洗牌生成器与随机数状态，逐行比较 `training.jsonl`；报告首个不一致的键或迭代（§4.4）。
- 诊断脚本：在固定诊断 rollout 上计算逐 N 的梯度诊断与优势方差分解（§8），只读检查点，不写回训练状态。

**必要验收**：

- 默认设置对原实现固定种子两次迭代的参数、关键 rollout 与指标一致；冻结场景/协议守护测试通过。正式运行中另按 §4.4 对 R0 做整段逐位比较。
- 比较脚本自检：同一检查点与自身比较为一致；改动任一张量的一个元素后能报告该键。
- 优势分解：合成轨迹上 Â^r + Â^v 与训练器的 GAE 逐元素一致（含截断与终止掩码），F3 下使用还原后的价值。
- ValueNorm 的时机：每个 rollout 统计量恰好更新一次，与 mini-batch 数无关（F3 与 F5 组合时同样如此）。
- F1 对非退化组的有包样本均值为 0、标准差近 1；无样本/零方差组有限且不产生除零，组合 F4 的单环境 N 组可用。
- F2 用不同 N、不同 active 数的合成案例验证 surrogate 与熵的环境权重；无有效样本环境被排除，尾批行为可追溯。
- F3 检查 normalize/denormalize 往返、原始单位 GAE/自举、统计只更新一次、跨 epoch 固定、检查点恢复一致；不把正常网络拟合误差错误要求为“与未归一化网络输出相同”。
- F5 检查完整轨迹覆盖、重放误差与有效样本一致，并验证通常 4 对 16 次优化器更新；开发测量峰值内存和吞吐。
- 筛选清单与实际结果必须恰含 2000–2255、N = 6/8、一次执行及完整评估窗口；所有方法公共随机数一致，旧验证/测试/确认输出不能混作主得分。已选模型验证保护失败不触发该运行内二次选模。
- 确认集必须经正式开关进入；与训练/开发/验证/旧测试不重叠；首末边界正确、每实例一次、同 UE 的种子跨 N 一致；v1 确认集路径不受影响。

## 10. 计算预算

下表列出环境时隙与评估回合，墙钟时间在第 0 阶段以开发吞吐重新估算。F5 的内存和更新方式不同，不能直接保证原来的耗时。

| 阶段 | 训练预算 | 评估工作量 |
|---|---|---|
| 第 0 阶段 | 工程、必要验收、已用开发实例吞吐测量 | 不提前读取新筛选集或确认集 |
| 第 1 轮 | 12 × 5M = 60M | 新筛选 60 × 512 = 30,720；已选模型旧验证 12 × 448 = 5,376；合计 **36,096 回合** |
| 组合验证 | 0 或 2 × 5M = 0–10M | 最多新筛选 10 × 512 = 5,120；旧验证 2 × 448 = 896；合计 **6,016 回合** |
| 第 2 轮 | 六个新增运行 × 5M = 30M；A-600 复用 | 新筛选 30 × 512 = 15,360；旧验证 6 × 448 = 2,688；合计 **18,048 回合** |
| 第 3 轮 | 3 × 20M = 60M | 新筛选 30 × 512 = 15,360；已选模型旧验证全网格 3 × 11 × 64 = 2,112；合计 **17,472 回合**；开发失败诊断另计 |
| A-near 补评 | 不训练 | 30 × 512 = **15,360 回合**；既有旧验证结果复用，全网格缺失点最多另 960 回合 |
| R0 复现检查 | 不另训练（R0 本属第 1 轮） | 逐位比较可忽略；仅当旧提交也不能复现时，第 1 阶段 A 的 10 个检查点补评筛选集 **5,120 回合**；旧提交 20 次迭代重跑约 1 分钟 |
| 训练诊断 | 不训练 | 36 个检查点 × 7 个 N × 12,800 环境时隙的固定诊断 rollout 及梯度计算，约 1–2 核·小时，以开发实测为准 |
| 确认集 | 不训练 | 学习检查点去重后约 6–12 个、本地规则七个、EDF 两版：约 84,500–117,500 回合 |

一般路径仍为 **150–160M 环境时隙**；B2 无训练变化时按 §6 停止，不发生重复长训及确认评估。各阶段的新筛选与旧验证不能重用彼此的结果，集合编码与实例不同；相同模型在相同集合、N 和实例上的既有结果才可缓存复用。

**不能把新方案计成每检查点只多 128 个回合而忽略验证保护**：若每个检查点同时评估新筛选和原六点验证，则是 512 + 384 = 896 回合；本设计采用“每检查点新筛选、每运行已选模型旧验证”。第 1 轮由第 2 版的 23,808（含 N = 2）增到 36,096 回合，约增加 52%。不含确认、失败诊断和 A-near 缺失网格补齐时，完整路径评估约 **86,976–92,992 回合**，比第 2 版多约 **38,784–40,832 回合**。

历史三种子 20M 长训约 9 小时，可作为第 3 轮参考；A-near 补评约 2 小时可作排程占位，实际以开发吞吐测量为准，不能从回合数直接保证耗时。确认集工作量仍约为 EXP-006 正式评估的 2.7–3.7 倍，按其约 3.5 小时吞吐粗推为 9–13 小时。筛选、验证、训练共享 CPU，本次扩集增加的是评估预算；以实测吞吐重新排程，不依据性能结果修改筛选或确认样本数。

## 11. 本次审阅决定

| 项目 | 决定 | 理由 |
|---|---|---|
| 范围 | 保留固定 OBS、训练校准与现有 C；不做信用分配/辅助表示 | 可以先检验现有训练瓶颈，保留明确边界 |
| F1、F2、F4 | 保留并细化 | 有具体诊断假设，须承认训练权重和计算量变化 |
| F3 | 改为全局 ValueNorm | 先建立原文建议的价值归一化基线，避免把按 N 扩展误作原文设置 |
| F5 | 加入单因素筛选 | 原文依据直接、现有配置可实现、符合信息边界；不预设一定有效 |
| 筛选数据与选模 | 新设 dev 2000–2255、N = 6/8；主 S_near 与时隙决胜，旧验证只评已选模型的副指标/保护 | 降低得分量化与旧验证反复使用的影响；不宣称消除选择偏差 |
| 得分与保留 | 保留 0.01 效果门槛、跨种子/固定末段与旧验证退化保护；另加筛选集上 F(6)、F(8) 的逐 N 保护 | 256 实例提高部署分辨率，仍需控制瞬时峰值和单种子驱动；防止 N = 6、8 互相抵消 |
| 因素组合 | 增加条件性的 COMB 验证与确定性回退 | 单因素有效不能推出组合有效 |
| 第 2 轮 | 保留 2 × 2，复用 A-600，修正 C 与长回合的解释 | 检验具体机制，不作风险最优或长期信用的过度归因 |
| 最终基线 | A-near 的 30 个长训检查点补评同一新筛选集、同一规则重选；保留 A-original 描述 | 排除不同集合或选模得分造成的混淆 |
| 确认集 | 建议 500 个部署，v2 独立登记，冻结后一次读取 | 提高门槛小幅增益的分辨力，保留协议核心 |
| 判读 | H1/H3 为容量点估计；H2 为 N = 8 优越性及 N = 6 非劣联合条件 | 避免天花板一票否决，并明确统计证据的范围 |
| R0 复现 | R0 检查点与 EXP-006 第 1 阶段 A 逐位比较；不一致时用旧提交区分实现错误与环境不确定性 | 设置与种子完全相同，可在看任何筛选结果之前确认默认路径未变 |
| 学习曲线 | 所有条件按环境时隙与优化器步数报告筛选集曲线 | 区分 F5 等因素的"更差"与"更慢"；只描述，不改保留规则 |
| ValueNorm 时机 | 每 rollout 更新一次，明确为偏离原实现；记录统计滞后 | 避免更新频率随 mini-batch 数变化；β = 0.99999 下统计量近似全程累计 |
| 优势分解 | 固定诊断 rollout 上按 N 分解奖励部分与价值部分的方差 | 检验门槛区优势主要来自奖励还是价值残差；只描述 |

以上为定稿设计（2026-10-03 用户批准）；不代表已经实现、完成机器登记或产生 EXP-008 实验结果。
