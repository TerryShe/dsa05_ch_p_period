# 信息边界探针补充：紧急标志丢失

上一份探针报告（RES-DSA05-PROBE-BROADCAST）中，B3 假设 AP 能读到每个发送者的 1 比特紧急标志，包括碰撞中、信号弱的发送者，这是该结果最大的保留。本补充保持 B3 的让行规则不变，只让标志在两种条件下丢失：

- **B3c（碰撞即丢）**：只有在上一时隙单独占用该子信道的发送者，其标志才被 AP 读到；只要碰撞就丢失，不看信噪比。
- **B3s（信噪比门限）**：只有上一时隙 SINR ≥ 0 dB 的发送才被读到，单独发送但信号弱的也会丢。SINR 由 AP 报告的该次发送的互信息换算。

## 1. 结论

1. **碰撞丢标志的影响不大：对学习策略，B3c 保留了 B3 的大部分增益**（ε = 0.01，与 none 的配对差值）：

   | 6 | M | +0.009 [+0.002, +0.020] | +0.008 [+0.002, +0.018] | +0.003 [−0.005, +0.013] |
   | 6 | best_local | +0.010 [+0.003, +0.020] | +0.010 [+0.003, +0.020] | 0.000 |

   | 8 | M | +0.015 [+0.004, +0.028] | +0.018 [+0.007, +0.033] | +0.005 [−0.001, +0.012] |

   - A-mix 与 M 在 B3c 下保留了 B3 增益的 70%–120%：
     - M 在 N = 8、10 上 B3c 略高于 B3，在抽样误差之内；
     - 原因可能是 B3c 推迟更少，B3 的部分推迟并不必要。
   - best_local 在 B3c 下，N = 8、10 只保留约一半（N = 6 全部保留）。它的失败 UE 碰撞中"共处"占比高（N = 8 时 0.31，学习策略为 0.14–0.17）。B3c 正好放弃了这一类：两个 UE 已经同在一个子信道上时，紧急一方的标志在碰撞中丢失。
2. **信噪比门限丢标志的影响大**：
   - 在 SINR ≥ 0 dB 的条件下，紧急 UE 的标志只有 17%–42% 能被读到。
   - B3c 下这一比例为 67%–92%。两者相减（各层 0.31–0.74）大致给出单独发送、但 SINR 仍低于 0 dB 的紧急发送所占比例的下界；两种模式的轨迹不同，所以只是近似。大部分丢失并非来自碰撞，而是紧急 UE 的接收信号本身弱。
   - N = 8 上，三组策略的 B3s 增益缩到 +0.005 至 +0.011，区间下限都在 0 或以下。
   - N = 10 上仍为正（+0.012 至 +0.048）。
3. **在任何丢失模型下，F(8) 都没有越过 0.95**：
   - B3c：A-mix 0.945 [0.922, 0.965]，M 0.949 [0.920, 0.978]；
   - B3s：A-mix 0.933，M 0.936。
4. **含义**：
   - B3 的增益主要来自"阻止不紧急的 UE 进入一个单独发送的紧急 UE 所在的子信道"，而不是化解已有的碰撞。
   - 所以紧急信息不必在碰撞中可靠送达，但**必须在低信噪比下可读**：紧急 UE 多半是远处的弱 UE。
   - 1 比特的标志可以用扩频或重复编码，在一个时隙约 1000 个信道使用上获得处理增益，物理上不难做到低于 0 dB 可读。但这需要在设计中写清楚，不能默认。

- **与上一份报告相同的部分**：策略、部署（开发切片 1000–1399，400 个）、种子、N ∈ {6, 8, 10}、紧急定义（slack < 3）、让行规则（只有不紧急的 UE 推迟）、结果计算、区间方法。
- **none 与 B3 不重跑**，直接与上一次运行的逐回合结果配对。
  - 运行前用修改后的代码重跑了 16 个回合：A-mix 第 0 层与 best_local，N = 8，none 与 B3 各 4 个实例。违约、推迟、发送、碰撞与统计计数都与存档完全一致。
  - 由修改后的汇总脚本重新生成上一份报告的 JSON，与已提交的逐字节相同。
- **B3s 门限**：0 dB，即每时隙互信息 ≥ 1000 比特（1 MHz × 1 ms）。门限是事先取的整数值，没有调。
- **标志统计**：
  - "发出"指上一时隙紧急且发送的 UE 数；
  - "读到"指其中被 AP 读到的数。
  - 两种模式下发出的数基本相同，每回合 N = 6 约 50–90、N = 8 约 110–210、N = 10 约 210–430。
- **运行**：2026-10-09 04:50–06:49，基于提交 2c384a9 加未提交的 B3c/B3s 改动。改动的 diff 存在 `outputs/probe-broadcast/flagloss-code.diff`。

## 4. 能说什么，不能说什么

能说的（描述性，限于本切片）：

- 对学习策略而言，B3 的价值不依赖"碰撞中也能读到标志"这一乐观假设。
- 价值依赖"弱的紧急 UE 单独发送时，其标志能被读到"。在 0 dB 门限下，大部分紧急标志读不到，N = 8 的增益基本消失。

不能说的：

- 不知道门限要低到多少才能保住增益：本补充只试了 0 dB 与"不看信噪比"两点。
- 不能说哪种物理实现可行。扩频或重复编码的标志、独立的控制资源、前导序列检测，都需要在设计中建模，包括检测概率与虚警。
- 仍不能说 N* 提高：所有丢失模型下 F(8) 都低于 0.95，且这是开发切片上的手写规则结果，策略没有重新训练。

## 5. 对 EXP-011 起草的影响

如果起草 EXP-011（把紧急广播写进观测），接收模型可取下面两种之一：

- "单独发送且 SINR ≥ θ 才读到"，θ 预先写定（例如 −10 dB，对应约 10 dB 的处理增益）；
- 把标志放在独立的控制资源上，作为另一种信令假设。

可以先在本切片上补跑 θ = −5、−10 dB 两点（约 1.5 小时），看增益在哪里恢复，再写定 θ。这一选择会影响设计，必须在新的切片上选择与评估，不能用本切片的结果直接定参数后又用它评估。
