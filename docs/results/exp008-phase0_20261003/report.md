## 3. 与设计文字不同或设计未写明的实现决定

1. **选模代码放在新模块 `select_exp008`**，没有改 `select_capacity_checkpoints`。这样 EXP-006 的选模路径逐字不变，后者仍然只接受验证集。
2. **筛选集通过登记的入口读取**：`evaluate_capacity --split dev --screen exp008-screen256 --formal`。设计 §9 写的是沿用 `--split dev --first-instance 2000 --instances 256 --grid 6 8`，现在比它更严格：
   - 普通的 dev 评估若与 2,000–2,255 重叠会被拒绝；
   - `--screen` 固定实例与 N，必须 `--formal`；
   - 输出中带有筛选集标记，`select_exp008` 只接受带这个标记的输出作为主得分。
3. **F1 的零方差组**：组内有效样本完全相同时只做中心化。原因是 float32 下相同值的均值可能差一个 ulp，(x − mean)/(std + 1e-8) 会把它放大到 ±1 量级。§3.1 的"零方差组的中心化优势为 0"由此得到保证。其余情况的公式与全局标准化相同（分母为 std + 1e-8）。
4. **F2 下日志中的 entropy** 是按环境等权后的均值，与实际进入损失的量一致；KL 与裁剪比例仍按样本平均，只作诊断。
5. **梯度诊断的口径**：
   - 损失取 ratio = 1 时的策略梯度代理损失，覆盖整个 rollout，不含熵项，也不切 mini-batch；
   - 优势标准化与损失加权按检查点自己的选项；
   - 各 N 的部分相加等于总损失，报告平均梯度范数、逐 rollout 范数均值、与总梯度的余弦、投影份额；投影份额相加为 1，可以为负。
6. **训练日志比较只用 EXP-006 已有的键**（不含计时字段），新增的诊断键不参与 R0 比较。
7. **第 2、3 轮配置尚未写**：它们取决于 B1、B2，按设计在相应结果产生后写出，届时再审阅。

## 4. 开发实测（非正式）

训练：6 个条件各一个种子并行，60 次迭代（107,520 个环境时隙），种子 101，非正式运行（预算覆盖），输出在 `outputs/exp008-phase0/throughput/`。

| 条件 | 时隙/秒 | 采集/更新（秒/迭代） | 每 rollout 优化器步数（演员/评论家） | 峰值内存 |
|---|---|---|---|---|
| R0 | 589 | 0.69 / 2.35 | 16 / 16 | 617 MB |
| F1 | 584 | 0.72 / 2.35 | 16 / 16 | 618 MB |
| F2 | 589 | 0.70 / 2.35 | 16 / 16 | 614 MB |
| F3 | 588 | 0.70 / 2.35 | 16 / 16 | 616 MB |
| F4 | 621 | 0.68 / 2.21 | 16 / 16 | 575 MB |
| F5 | 708 | 0.72 / 1.81 | 4 / 4 | 983 MB |

- F5 的优化器步数为 4，其余为 16，与设计 §3.2 一致；F5 的更新快约 23%，不是 4 倍，因为前向和反向的计算量相同。
- **F3 的方差下限**：这 60 次迭代中没有触发，rollout returns 的标准差约 0.30，运行统计的标准差约 0.56。训练后期违约率下降，returns 变小后下限可能触发；正式运行会记录触发比例，不调整下限。
- **逐 N 日志能正常记录**：例如 R0 在第 60 次迭代时，N = 4、8 标准化后的优势标准差约 0.4，N = 20 约 1.0。这只是 60 次迭代的冒烟结果，不作为证据。

评估与诊断：
- 筛选评估：用第 1 阶段两个 500 万检查点、已用过的开发实例 1,000–1,063、N = 6 和 8 做测量，256 个回合用时 119 秒（15 个进程），约 2.15 个回合/秒。
- 诊断：每个检查点 50 个诊断 rollout 约 87 秒（单核，含 F3 的检查点），GAE 分解的最大误差为 4.5e-7（float32 舍入）。

| 内容 | 工作量 | 估计 |

1. 启动 12 个正式训练；
2. R0 两个种子的第 1 个检查点产生后，与 EXP-006 第 1 阶段逐位比较；不一致就停止全部运行，此前不评估任何检查点；

4. 选模、验证集保护评估，以及 R0 验证结果与第 1 阶段的交叉核对；不一致按技术故障停止；
