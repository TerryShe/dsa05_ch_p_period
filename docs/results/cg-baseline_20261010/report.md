# 配置授权参照 N_CG：结果报告

## 1. 结论

1. **按预先写定的解读（设计 §5.3），结果为"CG 低于学习策略"**：
   - exp010-eval512 上，ε = 0.01 时 F(8; CG) = 0.805 [0.770, 0.838]；
   - CG − A-mix = −0.118 [−0.146, −0.092]，区间上限 < 0。
   - N = 6、8、10 三个负载下，CG 都低于 A-mix、M、best_local 与 N_EDF，所有配对差值的区间都不含 0（§3.2）。
2. **CG 甚至低于手写的本地规则 best_local**：
   - 配对差值在 N = 6、8、10 分别为 −0.059、−0.090、−0.035；
   - 验证集上 ε = 0.01 时 N\*(CG) = 2，best_local 为 4，N_EDF 为 20。
3. **放宽到 ε = 0.05 时 CG 接近本地规则，高负载时还更好**：
   - 验证集上 N\*(CG) = 8，与 best_local 相同；
   - N = 16 时 F_{0.05} 为 0.38，best_local 为 0.05。
   - 这说明 CG 消除碰撞的好处在高负载、宽松要求下才显现；在 ε = 0.01 的严格要求下，它的损失占主导。
4. **CG 的差距由两部分组成：不能跟随衰落，以及静态分配**（§5，额外的描述性诊断，未预先登记）：
   - 方法：对每个 UE，计算它在本设计的时机结构下独占整个资源格时的预测中断概率。
   - exp010-eval512 上 N = 8 时：
     - 512 个部署中有 76 个含有"独占也 > 0.01"的弱 UE；
     - CG 失败的 100 个部署中，有 72 个属于这一类；
     - 由此得到 F_{0.01}(8; CG) 的近似上限 0.852：在同样的时机结构下，任何资源再分配都超不过它，而 A-mix 为 0.923。（措辞过强，见 §10 更正）
   - CG 与 A-mix 的差距（每个种子层约 60 个部署）大致对半分：
     - 31–34 个是含弱 UE 的部署：A-mix 能满足，CG 即使独占也不能；
     - 27–28 个是其余部署：CG 因资源共享而失败，A-mix 全部能满足；
     - 反过来，没有一个部署是 CG 满足而 A-mix 不满足的。
   - 低负载时差距主要来自前者（N = 6：33–37 对 5–6），高负载时主要来自后者（N = 10：18–25 对 66–69）。
   - **弱 UE 部署对学习策略同样是难点**：
     - N = 8 时，A-mix 三个种子层共失败 118 个（部署 × 层），只有 1 个不属于这一类；M 共失败 102 个，也只有 1 个不属于这一类；
     - 只有 N_EDF 能满足其中除 4 个物理上不可行部署以外的全部。
5. **CG 的预测是准确的，所以失败不是估计误差**：
   - 各区间内预测中断概率与实际违约率很接近，例如 N = 8 时 0.0138 对 0.0144、0.0326 对 0.0327、0.0720 对 0.0728；
   - 最大最小分配也按设计工作：平均信噪比 < 10 dB 的 UE 得到窗口的 84%，≥ 30 dB 的只得到 24%；
   - 失败 UE 的平均信噪比中位数为 3.6 dB，窗口占比中位数为 0.90，即已接近用满。
6. **半静态预留的另一项损失是空闲**：
   - N = 8 时，分配出去的时机中只有 37% 真正用于发送；
   - 其余时机上，包已经提前译码完毕，而这些资源别的 UE 也不能用。
7. **不跳频的 CG-单信道几乎完全失效**：
   - exp010-eval512 上 F_{0.01} = 0.094、0.010、0.004（N = 6、8、10）；验证集上 N\* < 2。
   - f_D = 10 Hz 时，相干时间与业务窗口（10–40 ms）同量级，一个子信道在一个窗口内只有大约一个衰落状态。
   - 因此频率分集对 CG 是必要的。在 NR 中，这需要多个配置授权使用不同的频域资源；单个配置内的跳频只在两个位置间交替（设计 §3.6）。
8. **机制：CG 在 ε = 0.01 下有两项损失，学习策略基本避开了；CG 消除碰撞的收益抵不过它们**（§6，描述性）：
   - **不能按信道选子信道**（各负载下都有，低负载时为主）：
     - 一个窗口内每个子信道基本只有一个衰落状态，4 个子信道彼此独立；
     - CG 把发送固定分摊到 4 个子信道上，而能看到自身信道的方法可以集中到好的子信道上；
     - 单个 UE 时，后者达到中断概率 0.01 所需的平均信噪比低 3–4 dB；
     - N = 8 时，平均信噪比 < 3 dB 的 UE 在 CG 下发送时隙比例更高（0.58 对 A-mix 的 0.47），失败比例却也更高（0.98 对 0.66）。
   - **静态划分，不能按需挪用**（负载越高越重要）：
     - 分出去的时机 63% 空闲；
     - 衰落中的 UE 拿不到额外时隙；
     - N = 10 时，平均信噪比 6–10 dB 的 UE 在 CG 下有 13% 失败，A-mix 为 0。
   - 学习策略已经有第一项能力，缺的是第二项中的紧急度信息：
     - N = 8 时，< 3 dB 的 UE 仍有 54%–66% 失败；
     - N_EDF 两项都有，只失败 8%，总发送次数也最少。
9. **对后续的含义**（判读已由用户于 2026-10-10 确认）：
   - 按设计 §5.3，CG 作为部署方案的参照列入主表；
   - EXP-011（L1 紧急度信息）按原计划起草，参照仍是学习策略与 N_EDF；
   - 论文可以说，在 ε = 0.01 下，部署中的半静态方案（而且是对它有利的理想化版本）不如固定本地观测的分布式方法。这一点仍需在确认集上正式确认（§7）。

## 4. 诊断（设计 §5.2，描述性）

以下以 exp010-eval512、N = 8 的主变体为例；其他 N 与验证集见 `diagnostics.json`。

**分配**：
- 资源单元的分配比例为 99.8%，实际使用比例为 37%。没有使用的是提前译码后剩下的时机，以及没有待发包时的时机。
- 每个 UE 的时机数：快类平均 5.4 个（窗口的 54%），中类 9.5 个（47%），慢类 19.2 个（48%）。
- 按平均信噪比分组：

  | 平均信噪比 | UE 数 | 窗口占比 | 预测中断概率 | 实际违约率 |
  |---|---|---|---|---|
  | < 10 dB | 688 | 0.84 | 0.0080 | 0.0097 |
  | 10–20 dB | 1,855 | 0.53 | 0.00020 | 0.00024 |
  | 20–30 dB | 1,034 | 0.34 | 0.00007 | 0.00007 |
  | ≥ 30 dB | 519 | 0.24 | 0.00003 | 0.00006 |

  最大最小分配把资源集中给了弱 UE，符合设计。

**预测与实际**（逐 UE，按预测中断概率分组）：

| 预测中断概率 | UE 数 | 预测均值 | 实际违约率 |
|---|---|---|---|
| < 0.001 | 3,643 | 0.00007 | 0.00007 |
| 0.001–0.005 | 249 | 0.0023 | 0.0024 |

| ≥ 0.1 | 3 | 0.127 | 0.157 |

§3.5 的样本库预测准确，所以 CG 的失败不是因为预测不准。

**失败 UE**：
- 共 138 个，分布在 100 个部署中：快类 70 个，中类 51 个，慢类 17 个。
- 平均信噪比的中位数为 3.6 dB，窗口占比中位数为 0.90，预测中断概率中位数为 0.023。
- 也就是说，失败的主要是已经拿到大部分窗口的弱 UE。

**碎片**：
- 每个回合平均有 4.0 个 UE 在总资源还有剩余时因放不下而停止加时机，512 个回合中有 496 个出现这种情况。
- 但最终的分配比例为 99.8%，剩下的资源单元都被其他 UE 用掉了。
- 这项损失对 F 的影响没有单独量化；按 §5，它最多解释 N = 8 时 100 个失败部署中的 28 个。

**物理上不可行的部署**：N = 6、8、10 时分别有 2、4、5 个部署对任何策略都不可行。

**CG-单信道**：
- 预测同样准确，例如 N = 8 时 0.0329 对 0.0333、0.0719 对 0.0722。
- 但中断概率普遍很大：N = 8 时，平均信噪比 10–20 dB 的 UE 预测中断概率为 0.052；同组的主变体只有 0.0002。
- 失败 UE 共 2,458 个，平均信噪比中位数为 13.3 dB，不只是弱 UE。

## 5. 单 UE 上限（额外的描述性诊断，未预先登记）

**方法**（`scripts/cg_single_ue_ceiling.py`）：
- 对每个 UE，计算它独占整个资源格时的预测中断概率：用同样的放置规则放 P_i 个时机，用同一样本库计算。
- 如果一个部署中有 UE 独占时仍 > ε，那么在同样的时机结构下，无论怎样分配资源，这个部署都不可能满足要求。（措辞过强，见 §10 更正）
- 不含这类 UE 的部署比例，就是 F_ε(N; CG) 的近似上限。
- 之所以是近似，是因为协议对有限样本的违约数留有余量。例如验证集 N = 2 时，实际 F（0.953）略高于近似上限（0.938）。

**解读**：
- **CG 的上限**：
  - 在 ε = 0.01 下，N = 8 时，即使有最好的再分配，F 也不超过约 0.85，低于 A-mix 的 0.923；贪心分配在此基础上又损失约 0.05。（措辞过强，见 §10 更正）
  - 负载越高，部署中出现弱 UE 的机会越大，上限也越低。
- **差距的来源随负载变化**：
  - 低负载时，CG 落后主要因为弱 UE。CG 几乎满足不了弱 UE 部署（只有少数靠有限样本的余量通过），而学习策略能满足相当一部分：N = 6 时约 70%–85%，N = 8 时约 45%–65%，N = 10 时约 20%–45%。
  - 高负载时主要因为资源共享：CG 在非弱 UE 部署上的失败，学习策略几乎全部能满足。
  - 静态预留的空闲（§4：N = 8 时只有 37% 的时机被用到）是后者的一个原因，但这里没有单独量化。
- **学习策略的失败几乎都在弱 UE 部署上**。
  - N_EDF 能满足所有物理上可行的弱 UE 部署：它失败的 2、4、5 个部署恰好就是物理上不可行的那些。
  - 所以这些部署不是无法满足，而是分布式方法难以满足：弱 UE 需要的发送机会多，而其他 UE 看不到它有多紧急。这一解释没有单独检验。
- **机制**：见 §6。
- **ε = 0.05 时**：上限在 0.97 以上，所以宽松要求下 CG 的损失主要来自分配。这与 §3.1 中 ε = 0.05 时 CG 接近本地规则一致。

## 6. 机制分析（额外的描述性诊断，未预先登记）

`scripts/cg_mechanism.py`，结果在 `mechanism.json`。只用衰落样本库与已有的评估结果，没有跑新回合。

### 6.1 信道：窗口内几乎不变，子信道之间独立

样本库中 |h|² 的相关系数：

| 间隔（时隙） | 1 | 5 | 9 | 19 | 39 |
|---|---|---|---|---|---|
| 同一子信道 | 1.00 | 0.95 | 0.84 | 0.43 | −0.03 |

- 同一时隙、不同子信道之间的相关系数为 −0.006。
- f_D = 10 Hz 时：
  - 快类窗口（10 个时隙）内，每个子信道基本只有一个衰落状态；
  - 慢类窗口（40 个时隙）内才有明显变化；
  - 4 个子信道彼此独立。

### 6.2 单个 UE：按信道选子信道约值 3–4 dB

单个 UE 独占资源时，中断概率要达到 0.01 所需的平均信噪比（dB）。三种方式比较：
- **CG**：用 CG 规则放置的前 n 个时机。
- **每时隙选最好**：前 n 个时隙中，每个时隙用当前最好的子信道。
- **开始时选好**：窗口开始时选当时最好的子信道，此后不变。

后两种都只按顺序用前 n 个时隙，不挑时隙。

| 类别 | n | CG | 每时隙选最好 | 开始时选好 | CG − 每时隙选最好 |
|---|---|---|---|---|---|
| 快（P = 10） | 10 | 4.4 | 0.9 | 2.1 | 3.5 |
| | 5 | 9.2 | 5.2 | 5.4 | 4.0 |
| 中（P = 20） | 20 | 3.7 | 0.4 | 3.7 | 3.3 |
| | 10 | 8.0 | 5.0 | 6.2 | 3.1 |
| 慢（P = 40） | 40 | 2.7 | −0.6 | 3.7 | 3.4 |
| | 20 | 7.1 | 4.5 | 8.1 | 2.6 |

- **原因**：CG 的时机按规则在 4 个子信道间轮换，发送平均分摊到好坏不一的子信道上，一个子信道深衰落就损失约 1/4 的窗口。按信道选择则把发送集中在好的子信道上。
- **快类**：大部分收益只需在窗口开始时选对子信道（2.1 dB 对 0.9 dB），因为窗口内信道几乎不变。
- **慢类**：开始时选好后固定反而不如 CG 的分散（3.7 对 2.7 dB），因为 40 个时隙内信道会变。
- **与 UE 信噪比的关系**：按覆盖规则，最弱的 UE 平均信噪比约 1.3 dB。CG 失败 UE 的中位数是 3.6 dB（§4），正好落在这 3–4 dB 的差距里。
- **可用时机减半的代价**：所需信噪比升高约 4–5 dB。这对应 §6.4 的静态划分：份额固定时，衰落中的 UE 拿不到更多时隙。

### 6.4 解读

1. **不能按信道选子信道是主要损失，各负载下都存在**：
   - 弱 UE 在 CG 下发送得更多，例如 N = 8、< 3 dB 时发送时隙比例为 0.58，A-mix 为 0.47，失败却多得多（0.98 对 0.66）。
   - 所以问题不在发送机会的数量，而在发送落在不好的子信道上。这与 §6.2 的 3–4 dB 差距一致。
2. **静态划分是第二项损失，负载越高越重要**：
   - CG 分出去的时机 63% 因提前译码而空闲（§4），别的 UE 不能用；
   - 衰落中的 UE 也拿不到额外的时隙。
   - N = 10 时，平均信噪比 6–10 dB、单独服务完全没有问题的 UE，在 CG 下也有 13% 失败，学习策略为 0。
   - 这与 §5 的逐部署对照一致：N = 10 时，差距主要来自资源共享。
3. **CG 消除碰撞的收益在 ε = 0.01 下抵不过这两项损失**：
   - ε = 0.01 看的是尾部，尾部由弱 UE 的深衰落决定，而这正是 CG 最弱的地方。
   - 在要求宽松、负载高时，CG 的无碰撞才显出优势：验证集上 ε = 0.05、N = 16 时 F 为 0.38，best_local 为 0.05。
4. **对照 N_EDF，学习策略缺的是第二项中的紧急度信息**：
   - N_EDF 既按信道选子信道，又按紧急度分配时隙：< 3 dB 的 UE 只失败 6%–8%，总发送次数也最少。
   - 学习策略已能选子信道，在 3–6 dB 上远好于 CG；但它们看不到别人有多紧急，< 3 dB 的 UE 仍有 27%–75% 失败。
   - 这与信息边界探针中补上紧急度信息（B3）后 F 上升一致，但探针用的是手写规则，两者的联系没有直接检验。

## 7. 局限

- 两个集合都已读过。CG 没有参数，也没有选择，但结果仍只是开发阶段的依据。设计 §5.1 已定：正式比较放到下一次预先登记的确认集（备用池 31,000 起），与 EXP-011 一起做。
- CG 的分配是贪心最大最小，不是最优分配。§5 的上限说明，在同样的时机结构下，更好的分配在 N = 8 时最多再提高约 0.05，仍低于 A-mix。（措辞过强，见 §10 更正）但这一上限依赖本设计的时机结构：每时隙一次发送、满功率、按规则放置。其他结构，例如功率控制或多时隙重复编码，没有覆盖。
- 设计 §3.6 列出的理想化都对 CG 有利（理想增量冗余、准确的信道统计、时机位置任意），所以实际的 NR 配置授权预计不会好于这里的结果。
- §5 与 §6 不是预先登记的分析，只作描述，不作为判读依据。
- §6.2 假设 UE 准确知道当前信道。学习策略的观测含自身在各子信道上的增益，但这里没有核对它们实际如何选择子信道。
- §6 的机制来自配对统计与单 UE 计算，没有做"给 CG 加上信道选择或按需挪用"之类的对照实验；这样的变体也已不再是 NR 的配置授权。

## 10. 更正（2026-10-10，DES-DSA05-CG-OPT 定稿时加入；数值不变）

- §1 第 4 条、§5 与 §7 把单 UE 上限说成"在同样的时机结构下，任何资源再分配都超不过它"，这说过头了。
- 上限中每个 UE 独占时的中断概率，用的是 CG 自己的放置规则，不是所有放置中的最小值。另一种放置可能让同一个 UE 的中断概率更低，所以"独占也 > 0.01"的 UE 在别的放置下未必仍 > 0.01。
- 开发部署中已有反例：实例 22（N = 8）里，贪心在有其他 UE 时为某个 UE 找到的放置，比它独占时的规则放置略好（0.0063 对 0.0067）。
- 因此 §5 的数值应读作**按本设计放置规则的近似上限**，不是严格上界。表中数值与 §3 的判读都不受影响。
- 优化的静态配置（CG-opt，DES-DSA05-CG-OPT）会给出改进的近似上限（最好已知的单 UE 放置）与一个严格但很松的界（每个时隙都用最好的子信道）。
