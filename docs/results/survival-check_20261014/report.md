# 逐包重放：截止期违约是否成串出现（生存时间方向的可行性检查）

本报告是实验记录，不是论文文本。

## 1. 结论

1. **违约明显成串出现**，所有方法都如此：
   - 学习方法（M、U、M+Y）中，一个包违约之后，同一 UE 的下一个包违约的概率为 10–15%；而全部 UE 的平均违约率只有 0.016–0.10%，最差 UE 的平均违约率也只有 0.08–0.7%。
   - 按每个 UE 自己的违约数作独立参照（随机打乱位置），相邻两个包都违约的次数是参照的 4–14 倍。
2. **以生存时间等于一个传输周期计（连续两个包违约即服务中断）**，在 20 秒的评估回合中：
   - 学习方法在 N = 8、10、12 上有 7–24% 的部署至少出现一次中断，是独立参照的 2–5 倍；
   - CG-opt 为 26–61%，best_local 为 16–47%。
3. **多数连续违约不是物理上无法避免的**：集中式 N_EDF 只在物理上无法送达的包上违约（53/53、63/64、68/70）。这类包造成的相邻违约对，在每个学习方法中约 65 对（5 个种子层），而学习方法的相邻违约对为 146–1,215 对。
4. **现有方法降低了违约率，但没有降低违约后的风险**：U、M+Y 的违约率比 M 低 20–40%，违约后下一个包的违约概率却都在 10–15%。现有训练目标（失败包总数）不区分孤立违约与连续违约。
5. 在"所有 UE 距 AP ≥ 10 m"的部署上（与场景 v2.1 完全相同），结果几乎一样。

所以，生存时间约束在本场景中是一个非平凡的问题。

## 2. 方法

- **回合**：exp011b-eval128 的 128 个部署，N = 8、10、12；方法为 M、U、M+Y（EXP-011b 选出的检查点，5 个种子）、N_EDF、CG-opt、best_local。共 6,912 个回合，每个回合逐 UE 的违约数都与 EXP-011b 的正式评估一致（全部核对通过）。
- **逐包结果**：每个 UE 在评估窗口内的包按截止期排序，记录每个包是否违约。
- **独立参照**：保持每个 UE 的违约数 m 与包数 M，把违约随机放在 M 个位置上。相邻违约对的期望为 m(m−1)/M；部署中"至少一次连续两个违约"的期望概率由每个 UE 200 次打乱估计。这个参照吸收了 UE 之间违约率的差别。
- 脚本为会话中的临时脚本（`survival_replay.py`、`survival_analyze.py`、`survival_cond.py`），输出在 `outputs/survival-check/`，未入库。

## 4. 解释范围与局限

- 只用已读的开发切片，描述性，不是任何判据的检验。
- 独立参照假设每个 UE 在回合内的违约率不变；回合内的非平稳（例如策略隐状态的漂移）也会表现为成串。
- 回合长度 20 秒；"至少一次中断的部署比例"随回合长度增加。
- 慢类的计数很小，比例不稳定。
- 生存时间取几个周期须依据 TS 22.104 的用例写定；这里只取了最严格的一个周期。
