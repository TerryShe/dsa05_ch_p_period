## 3. 实现中对设计的补充（需要确认）

### 3.1 部署在 N 之间嵌套

规范 §2.3 写的是"衰落种子由（集合，N，实例，执行序号）派生"。实现改为：每个 UE 一个种子，由 `SeedSequence([基准, 集合编码, 实例, 执行序号]).spawn(N)` 的第 j 个子序列给出，不含 N；执行种子同样处理。拓扑按 UE 顺序逐个抽取，相位按 UE 顺序抽取，类别为 j mod 3。

结果：实例 i 在 N 个 UE 下的部署，恰好是任何更大部署的前 N 个 UE。

好处：
- F(N) 各点使用公共随机数，差异只来自新增的 UE，曲线更平滑，N\* 的抽样误差更小；
- 正交上界的 s\* 随 N 单调不减，可以二分查找，使计算量减少约一半。

代价：
- 同一实例在不同 N 下不再相互独立。这对每个 N 上的 F 没有影响；N\* 的 bootstrap 已经在各 N 之间联合重抽实例。

建议采用，并在冻结时把规范 §2.3 的这句话改为"不含 N，逐 UE 派生"。

### 3.2 正交上界加入整时隙割（可选分析，记录备查）

规范 §7 的正交 LP 只要求每个（时隙，子信道）的使用份额之和不超过 1。开发实例上发现这个上界几乎没有信息：一个需要 1.2 个时隙的包实际要占 2 个整时隙，LP 却把第二个时隙剩下的 0.8 分给别的 UE。以开发实例 21 为例：
- 不加割时，N = 32 与 40 都可行（s\* = 2.4 × 10⁻⁵）；
- EDF 的 F(28) 只有 0.17。

实现加入了整时隙割：

  Σ_{t∈窗口(p), k} x_{i,t,k} ≥ m_p (1 − z_p)

其中 m_p 是该包独自在每个时隙用最好子信道、满功率、先用最好的时隙时所需的最少时隙数。z_p 解释为"该包违约"的松弛指示变量：实际执行中违约的包取 1，否则取 0，所以 V_i = Σ z_p。在这种解释下，原有约束和这条割对任何正交调度都成立，上界仍然有效；不可送达的包直接取 z_p = 1。

- 手算例子：两个 UE 共用一个子信道，每个包需要 2 个整时隙、窗口 2 个时隙。不加割时 s\* = 1/3，加割后为 1/2，后者才是正确的。
- 加割后，实例 21 在 N = 28 时的 s\* = 0.0005（仍可行）。

`mac` 上界允许多个 UE 叠加在同一（时隙，子信道）上，这条割对它不成立，所以 `mac` 保持原样。它是允许 SIC 的信息论上界，本来就可能偏松（规范 §7 已写明）。

### 3.3 LP 计算方面的调整（可选分析，记录备查）

- **`mac` 只在必要处求解**：正交可行时 `mac` 必然可行（s\*_mac ≤ s\*_orth）。所以先对 `orth` 做二分，`mac` 只在 `orth` 不可行的网格点上求解。
- **求解器**：HiGHS 内点法，关闭交叉（crossover），单线程，每个 LP 时限 3600 s。
  - 第一次运行用 scipy 的 `linprog`（含交叉），在 s\* > 0 的紧实例上单个 LP 可超过数小时，15 小时只完成约 20 个实例，已中止。
  - 关闭交叉后，目标值的原始–对偶误差约 10⁻⁹，远小于判定所用的 ε。
  - 超时或未得到最优解的 LP 按"可行"计（上界仍然有效），并单独计数。

### 3.4 规则的具体形式（规范 §8 留到第 0 阶段写定）

- **p 坚持**：选当前自身增益最大的子信道、满功率；按无干扰速率算松弛量 s，s ≤ 0 时必发，否则以 min(1, a/(s+1)) 的概率发送。
- **机会式阈值**：用当前自身增益除以上一时隙干扰（扣除自己）估计各子信道满功率速率 r；当 r ≥ θ × 剩余比特/剩余时隙，或按 r 计算的松弛量 ≤ 0 时，在 r 最大的子信道上满功率发送。
- **周期预约**：预约（偏移 o，子信道 c）；每个包从到达后第 o 个时隙起在 c 上满功率发送直到译码；连续 `failures` 个包违约后重抽 o ∈ {0, …, ⌊offset·P⌋−1} 与 c。
- **paced_sticky_csi**：链路评分为当前自身增益 / 上一时隙干扰；评分落后最好者超过 switch_db 时以 switch_probability 改选；功率取满足 (1+margin) 节奏的最低档。
- **EDF**：实现了两版。
  - 规范版：按松弛量排序。
  - `defer_hopeless`：松弛量为负的 UE 排到最后。

### 4.2 失败的形态

- **本地规则在小 N 下的失败是边缘性的**：
  - N = 4 时，paced_sticky_csi（margin = 2）与 p 坚持（a = 16）各只有 4/256 个 UE 的违约率超过 1%，违约率中位数约 2%；
  - 这些 UE 全是快类（窗口 10 个时隙），距 AP 中位数 94 m（全部 UE 为 70 m）；
  - 由于"所有 UE 都满足"才算可行，一个边缘快类 UE 就使整个部署不可行。
- **N = 8 时本地规则普遍失败**：p 坚持 132/512 个 UE 超过 1%，paced_sticky_csi 24/512。
- **EDF 的失败是过载**：
  - 信道占用率（发送的 UE·时隙 / 子信道·时隙）N = 20 时 0.74，N = 24 时 0.90，N = 28 时 0.99；
  - N = 24 时 13% 的 UE 超过 1%，各类别相近，距离中位数 81 m；
  - defer_hopeless 版在 N = 24、28 时超过 1% 的 UE 更少（6%、37%，规范版为 13%、63%），但 F 几乎相同，N\* 也相同。
- **不可送达的包**：EDF 全部回合 16,768,000 个包中 1,386 个（0.008%）；没有任何回合是"全员不可行"的。§5.3 的 1% 判据远未触及，覆盖规则无需调整。

### 4.3 LP 上界：已停止，不作为前置条件

- **完整 LP**（`mac` 加带整时隙割的 `orth`，12 个进程）：开始约 2 小时后才完成第 1 个实例（单个实例约 2.1 小时单核），64 个实例预计需要约 11 小时。按用户决定于 2026-10-01 中止，没有可报告的汇总。
- **单实例的观察**（开发实例 21，不代表整体）：
  - 带整时隙割的正交上界在 N = 24、28 时可行（s\* ≈ 0、0.0005），所以该实例的 N_orth ≥ 28；
  - 同一实例上，合并子信道的松弛（`orth_agg`）在 N = 28 时给出相同的 s\*，在 N = 32、36 时不可行（s\* = 0.018、0.095）。
  - 这只说明集中式调度在该实例上至少还有约 2 个网格点的余地，不足以推断整体。
- **合并子信道的松弛**（`orth_agg`：每个时隙至多 K 个 UE，各用自己最好的子信道）是正交调度承载能力的有效上界，比完整正交 LP 略松，但快约 9 倍（N = 28 时 37 s 对 332 s）。它在 4 个进程上跑完了开发实例 0–63，结果只作参考，不作为判据（`orth-agg-summary.json`）：

  | ε | N\* | 24 | 28 | 32 | 36 | 40 |
  |---|---|---|---|---|---|---|
  | 0.01 | 24（bootstrap：24 占 58%，28 占 42%） | 1.00 | 0.94 [0.88, 0.98] | 0.44 | 0.02 | 0 |
  | 0.05 | 28 | 1.00 | 1.00 | 0.78 | 0.14 | 0 |

  - N ≤ 20 时全部可行。
  - 259 次求解，单次最长 436 s，合计约 6 小时单核。
  - 4 次求解以 Unknown 结束（实例 30、45 的 N = 24，实例 49、53 的 N = 32），按规则计为可行，上界仍然有效。
  - 解读：即使知道整段未来信道、集中调度且允许时隙内分享，正交调度在 ε = 0.01 下的承载能力也只有 24–28。N_EDF = 20 离这个上限约一个网格点；本地规则（N\* < 4）离它很远。分布式协调的主要差距在本地规则与 N_EDF 之间，而不在 N_EDF 与理论上限之间。

## 7. 计算成本

- **方法评估**：20,000 个时隙的回合，N = 24 时单回合约 4–6 s（单核）。本次 13 个规则 × 8 个 N × 64 个实例共 6,656 个回合，14 个进程约 45 分钟。
- **LP 上界**（不作为前置条件）：完整 LP 每个实例约 2 小时单核；`orth_agg` 每个实例约 6 分钟单核（开发实例 64 个合计约 6 小时单核）。
