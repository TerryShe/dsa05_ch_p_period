## 方法和适用范围

C-FAST 针对 5G 与 TSN 协同：异构周期流若只给单个 CG，会周期性出现资源冲突。它预配置多个 CG，并为各 CG 配置一个按包的激活向量，UE 可据此选择本次可用配置，避免逐包下发激活消息。调度还约束每个 UE 的 CG 数量（论文按当时 3GPP 的最多 12 个考虑）。这是作者提出的增强安排，不应把整套 activation vector 机制写成 NR 已普遍部署的现行标准。

评价为工厂 LOS、固定 MCS 12，关注可满足的调度实例、碰撞、CG 数量与时延。其“reliability”首先是所有包均得到无冲突且满足时限的资源分配，不能与 Jakes 衰落下的真实按期交付概率直接等同。

## 对 DSA05 的最重要启示

**周期业务的低开销协调已有很强的非学习路线**。不能把“去掉集中调度、利用周期、减少每包控制信令”本身当作新贡献。静态配置也不必局限于“每 UE 永久占一个固定子信道”。

V2 与它的关键区别应落实在以下问题：预先安排已消除周期碰撞后，在时变衰落与弱 UE 产生的紧迫状态下，额外的即时摘要还能带来多少净收益。这个问题与当前 CG-opt 诊断方向一致，但 CG-opt 只是项目内优化基线，不等于所有配置授权方案的最优解。

| 维度 | C-FAST | DSA05 V2 拟方法 |
|---|---|---|
| 调度端 | 基站根据 TSN 周期与时限集中预计算 | UE 根据本地 CSI/剩余工作量和摘要逐时隙决策 |
| 控制时序 | CG + 激活向量预配置；执行少逐包消息 | 上行 flag + AP 按子信道广播摘要 |
| 主要难点 | 异构周期资源重叠、配置数量限制、端到端时限 | 衰落机会、弱 UE 紧迫性与动态多用户干扰 |
| 学习/功率控制 | 不是 MARL；固定 MCS 的资源调度 | MARL、子信道/功率/时机联合选择 |

## 应研究的实验与新方向（本项目建议）

1. **把静态参照解释准确**：CG-opt 是否允许周期内多个资源、跨子信道模式、以及多配置选择应写明。若不支持，应将结论限定为当前基线，而非“配置授权不行”。
2. **一个有价值的中间信息等级**：周期性预配置的多子信道备选 + 本地 CSI 选择 + 少量紧急重配置。它可能以很低的即时信令获得不少动态收益，也可能保留碰撞，需要实测。
3. **混合协议方向**：大多数时段沿用 CG，只在弱 UE 接近截止期时发布事件驱动摘要。以每成功按期包的控制资源、最差 UE P2 与配置更新成本比较持续广播方案。
4. **公平的资源口径**：预配置向量的成本按部署/业务变化时刻摊销；V2 持续广播成本按每时隙累计。不能把 CG 的一次配置当成每时隙开销，也不能把持续摘要只计成一次 K bit。

这些方向不要求现在修改冻结实验；可以作为 EXP-011/012 后的候选协议扩展。对当前论文，至少需要引入本工作作为 CG 基线设计与相关工作的约束。
